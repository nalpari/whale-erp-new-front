# 정책

## 누가 받는다

* 플랫폼 마스터·관리자는 **문의사항·도입문의**의 접수와 처리 상태 변경을 받는다. — `S-JUWPXF`
* BP·가맹의 마스터·관리자는 **소속 범위 직원**의 근로계약 날인·거부·만료·갱신 예정과 **자기가 등록한 문의**의 답변을 받는다. 가맹 점포 직원의 근로계약 알림은 가맹마스터·가맹관리자가 받고, BP 마스터·BP 관리자는 그 직원이 **본사 제공 동의**를 했을 때만 받는다. — `S-JUWPXF` · `NOTIFY-13`
* 가입자 연결 확인 필요와 소속 확인 거절은 그 직원의 **근로계약서 초안을 쓴 관리자**가 받는다. — `S-JUWPXF`
* 관리 권한이 있거나 당사자인 업무의 알림만 보인다. 권한이 없으면 알림함도, 이어지는 상세도 들어가지 못한다. — `S-GDUNIT`
* 받는 사람은 알림이 생길 때 정한다. 뒤에 매핑·권한·점포 유형이 바뀌어도 이미 받은 알림을 다시 거르지 않는다 — 결정 A (2026-10-13 재영)
* 알림 유형은 열 가지로 한정한다 — 문의사항 접수, 도입문의 접수, 문의사항 답변, 도입문의 처리 상태 변경, 근로계약 날인·거부·**만료**, 가입 연결 보류, 소속 추가 확인 거절, 계약 갱신 예정. 만료는 날인 기한 30일이 지나 계약이 만료될 때 그 계약을 맡은 사업자 관리자의 알림함으로 간다(2026-10-07 재영). 메일이 필요하면 업무 쪽이 따로 보낸다(운영 정책 NTF-03, 2026-10-13). — `S-JUWPXF`

## 읽음과 중복

* 읽음은 **사람마다 따로**다. 같은 알림을 다른 관리자가 읽어도 내 미확인 수는 줄지 않는다. — `S-GDUNIT`
* 눌러 들어가면 **그것으로 읽음**이다. 처리했는지는 알림함이 아니라 원래 업무의 상태가 안다. — `S-GDUNIT` · `NOTIFY-1`
* 같은 사건으로 같은 사람에게 같은 알림을 두 번 만들지 않는다. — `S-JUWPXF`
* 종 아이콘은 미확인 수와 최근 몇 건, 알림함 페이지는 걸러 보고 지나간 것을 찾는 자리다. — `S-GDUNIT` · `NOTIFY-2`
* 알림함 목록은 목록 공통 규칙대로 페이지로 나눈다. — `S-GDUNIT`

## 기한·채널

* 갱신 예정 알림은 계약 종료일 **30일 전에 한 번**만 만든다. — `S-JUWPXF`
* 운영 알림은 **알림함에 넣는 일만** 한다. 메일이 필요하면 업무 기능이 메일 발송(MailService.send)을 따로 부르고, 결과는 메일 발송 이력에 남는다. 알림 줄에는 메일 결과를 담지 않는다. 메일 버튼은 업무 화면으로 바로 가고, 메일로 봐도 알림함 읽음은 맞추지 않는다. — `F-SYOZEO` · 운영 정책 NTF-03 v114 (2026-10-13 재영). NOTIFY-3 의 「알림 한 줄에 발송 결과까지」는 메일에 대해 이것으로 바뀌었다
* 모바일 푸시는 없다 — 관리자 전용 앱이 없다. 문자 발송도 1차에 없다. — `F-SYOZEO`
* 직원에게 가는 앱 푸시와 알림톡은 이 영역이 아니라 직원 알림 기능의 것이다. — `F-SYOZEO`

## 알림 템플릿

* 템플릿은 채널 + 템플릿 이름 + 템플릿 코드로 구분한다. 알림 유형·발송 용도 공통코드는 두지 않는다. 채널은 운영 알림·앱 푸시·메일·알림톡 넷이고, 템플릿 코드가 겹칠 때만 저장을 막는다 — `F-TZPHZT` · `NOTIFY-11`
* 앱 푸시 템플릿은 수신 설정 묶음(근로계약서·근무스케줄·TO-DO·급여명세서) 하나를 고른다. 직원 알림 수신 설정이 이 묶음으로 켜고 끈다 — `F-TZPHZT` · `NOTIFY-11`
* 플랫폼 마스터·플랫폼 관리자만 등록하고 고친다 — `S-QQPYIU`
* 등록으로 새 템플릿을 더하고, 기본 40건과 등록한 것 모두 모든 항목(채널·유형·템플릿 코드·카카오 템플릿 코드·변수 목록·제목·본문)을 고친다. 지우지 않고 사용 / 사용 안 함으로 끄며 사용 안 함은 흐리게 보인다 — `F-TZPHZT` · `NOTIFY-10`
* 변수 목록은 화면에서 넣고 고친다(변수 이름·표시 이름·필수·예시 값). 본문 위 변수 단추는 이 목록에서 그린다. 목록에 없는 변수나 빠진 필수 변수가 있으면 저장하지 않고 위치를 알려 준다. 「버튼 링크」 체크 칸은 메일·알림톡에서만 보이고, 켠 변수는 필수 변수 검사에서 빠진다(NOTIFY-20). 등록 화면의 변수 목록은 빈 표로 시작한다. 저장할 때마다 바뀌기 전 문구를 변경 이력에 남기고, 기본 문구로 되돌리기는 기본 40건에만 두고 제목·본문·변수 목록만 되돌린다 — `S-QQPYIU` · `NOTIFY-10` · `NOTIFY-17` · `NOTIFY-18`
* 앱 푸시 탭은 직원 근무 앱 알림함에 쌓이는 문구까지 맡는다. TO-DO 배정은 푸시 없이 알림함에만 쌓인다 — `S-QQPYIU` · 앱 `NOTI-1`
* 알림톡도 수정 화면에서 본문을 고친다. 카카오 검수를 받은 문구와 한 글자라도 다르면 발송되지 않아 본문 위에 그 안내를 둔다. 제목은 없고 승인 상태도 두지 않는다. 배포는 필요 없다 — `S-HIBBDL` · `NOTIFY-6` · `NOTIFY-8`
* 운영 알림·앱 푸시·메일은 제목과 본문이 필수라 비우면 저장하지 않는다. 알림톡은 제목이 없고 본문만 필수다. — `S-QQPYIU` · `S-HIBBDL`
* 1팀 화면에서 나가는 관리자 메일 8종(회원가입 완료, 신규 BP 가입 알림, BP 신규 등록, 플랫폼 관리자 계정 생성, BP 관리자 계정 생성, 비밀번호 초기화, 임시 비밀번호 발급, 회원 탈퇴 완료)도 메일 탭의 템플릿으로 두고 문구를 여기서 고친다. 1팀 공통코드 메일 유형은 쓰지 않는다. 메일 탭은 24건이다(급여명세서 발송 메일 둘 포함, 2026-10-13) — `F-TZPHZT` · `NOTIFY-9`
* 템플릿마다 **템플릿 코드**를 둔다. 등록할 때 채널 접두(NTF_·PUSH_·EMAIL_·TALK_)만 채우고 나머지는 운영자가 넣는다. 기본 40건의 코드는 지금 값 그대로다. 등록·수정 모두 저장 전에 「저장하시겠습니까?」 확인창을 띄우고, 이미 있는 템플릿의 코드를 바꿨으면 같은 확인창에 발송 코드도 함께 바꿔야 할 수 있다는 경고를 보인다(2026-10-13 재영). 코드를 바꾸면 지난 운영 알림의 구분 표시가 비어 보일 수 있는데 감수한다(운영 정책 NTF-24). 알림톡의 카카오 템플릿 코드와는 다른 값이다 — `F-TZPHZT` · `NOTIFY-10` · `NOTIFY-11`
* 앱 푸시는 제목 40자·본문 100자까지이고 넘으면 저장하지 않는다. 메일 본문은 일반 글만 쓰고 머리·꼬리·버튼은 공통 메일 틀이 붙인다 — `S-QQPYIU` · `NOTIFY-4` · `NOTIFY-5`
* 템플릿을 읽지 못하면 어느 채널이든 그 알림은 보내지 않고 서버 로그와 호출한 쪽 실패로 남긴다. 화면에는 보이지 않는다 — `S-QQPYIU` · `NOTIFY-19`
* 알림톡을 되돌릴 때는 확인창에 「카카오 템플릿 코드는 바뀌지 않으니, 검수받은 본문과 맞는지 확인해 주세요.」를 보인다. 채널이 바뀌어 기본 문구가 지금 채널에 맞지 않으면 되돌리지 않는다 — `NOTIFY-18`

* `/notifications` — 데모 칸 구성(선택 · 미확인 점 · 알림 · 구분 · 일시)에 요건의 「내용」(제목 아래 둘째 줄)과 「관련 업무」(근로계약 #41 꼴) 칸을 더했다. 전체 선택은 툴바 체크박스(공통 `DataTable` 은 고치지 않는다), 모두 읽음 · 선택 삭제 확인창, 페이지당 20·50·100. 화면 상태는 URL.
* `/notifications/[id]/open` — 알림함 · 종이 여기로 온다(메일 버튼은 업무 화면으로 바로 간다, 운영 정책 NTF-03 v114). GET 으로는 아무것도 바꾸지 않고 화면에 뜬 뒤 서버 액션으로 읽음 처리하고 업무 화면으로 보낸다(브라우저 미리 불러오기 · 메일 검사기가 읽음을 일으키지 않게).
* 갈 업무 화면은 알림을 만든 업무 쪽이 `notify` 의 `link` 로 넘긴 관리자 웹 경로다(NOTIFY-16, 2026-10-13 재영). 화면은 경로를 모르고 `safeLink` 로 관리자 웹 안의 경로인지만 다시 본다. 링크가 없으면 알림함으로 돌아와 「이동할 화면이 없습니다」를 보인다. 들어간 업무 화면은 그 시점 권한으로 판정한다 — 받은 알림은 받을 때 기준으로 계속 보인다(2026-10-13 재영).
* 종 `NotificationBell` — 공통 틀(AdminFrame)의 헤더가 `NotificationBellSlot` 으로 그린다. 운영 알림함은 2026-10-15 공통 틀에 맞춰 자기 헤더 · 바깥 틀 · `ErpRoot` 를 걷고 `PageBar` 부터 그린다. 근로계약 화면도 2026-10-16 같은 방식으로 임시 헤더 · 바깥 틀 · `ErpRoot` 를 걷어, 종은 공통 틀 헤더의 것 하나만 보인다. 빨간 점이 박힌 `alarm.svg` 대신 점 없는 `alarm-bell.svg` 를 쓴다. `AlarmLink` 는 그대로 둔다(디자인 견본이 쓴다).
* 읽음이 바뀌면 모든 화면을 다시 그린다 — 종이 화면마다 서버에서 그려진다.

## 2026-10-13 결정 (NOTIFY-12~15, 재영)

* NOTIFY-12 — 알림에 제목 칸(`notifications.title`)을 두고 목록 · 종 팝오버가 쓴다.
* NOTIFY-13 — 가맹 점포 계약 알림은 가맹마스터 · 가맹관리자, BP 마스터 · BP 관리자는 그 직원이 본사 제공에 동의했을 때만.
* NOTIFY-14 — 운영 알림은 열 가지 그대로. 만 19세 미만 가입 불가 · 일괄 저장 완료 · 실패는 각 화면 상태로 보인다.
* NOTIFY-15 — 템플릿을 못 읽으면 운영 알림을 만들지 않고 서버 로그만 남긴다.
* NOTIFY-16 — 알림을 눌러 갈 업무 화면은 알림을 만드는 업무 쪽이 링크로 넘긴다. 운영 알림 쪽 경로표는 두지 않는다.
