* `src/app/contracts/[contractId]/edit/` - 임시저장 이어 쓰기. 작성 화면과 같은 폼을 `GET /contracts/:contractId` 값으로 열고(`fromDetail`) `PUT` 으로 저장한다. 임시저장이 아니면 안내만 보이고, 없는 계약은 404. 임시저장 삭제는 여기에만 있다 — 폼 위쪽 버튼 줄의 취소와 임시저장 사이(`ContractForm` 의 `deleteButton`). 공통 `ConfirmDialog` 로 한 번 더 묻고 서버 액션(`../actions.ts`)이 `DELETE /contracts/:contractId` 를 부른 뒤 목록으로 간다. 실패하면 확인창 안에 이유를 보인다. 근무지 · 한글 선택지는 두 화면이 `load-form-data.ts` 를 같이 쓴다.
* `src/app/contracts/new/` - 근로계약서 초안 작성. `docs/demo/staff/contracts-new` 를 공통 컴포넌트로 옮겼다. 근무지는 `GET /stores/options`(근무지 선택지 — 폐점 빼고 이름순), 저장은 서버 액션(`actions.ts`)이 `POST /contracts` 를 부르고 성공하면 목록으로 간다. api 의 400 · 404 · 409 문장을 그대로 보인다. 근무시간 · 휴게시간은 고른 요일 모두에 같게 들어가고 주 소정근로시간을 바로 셈한다. 만 19세 미만(계약 시작일 기준)이면 저장 버튼을 막는다. 주휴일 칸은 7일 근무를 협의하기 전까지 숨긴다(`hidden`). api 는 NULL 로 저장한다. 휴대전화번호는 칠 때 하이픈이 들어가고(010 은 3-4-4, 그 밖은 3-3-4) 저장은 숫자만, 생년월일은 `DateField autoHyphen`. 「임시저장」은 임시저장(DRAFT), 「초안 저장」은 발송 대기로 남기고 둘 다 아직 초대를 보내지 않는다. 임시저장은 이름 · 휴대전화번호 · 근무지 · 직무 · 고용 형태가 있어야 하고(운영 정책 CTR-02, 고용 형태는 라디오라 늘 값이 있다) 비운 칸은 보내지 않는다(근로계약은 키만 NOT NULL). 저장 버튼 옆 안내 문구는 아직 「직무만」이라 화면 코드를 고칠 때 맞춘다. 근무 장소(계약서 조항) 칸이 있다. 목록은 비어 있는 기간 · 급여 · 상태를 「-」로 보인다. 종이 계약은 아직 없다(데모와 다른 점). 근무요일 · 근무시간 · 휴게시간이 한 줄이고, 소정근로시간 표 아래 시급 · 읽기 전용 월급(정직원은 연봉도)이 한 줄, 그 아래 급여 표가 고용 형태에 따라 바뀐다(현업 엑셀 견본, 2026-10-13. 흰 칸은 입력, 회색 칸은 셈한 값이고 셈한 값은 저장하지 않는다). 정직원은 연봉(월급 × 12)과 「비과세 항목」(식대 · 자가운전보조금 · 육아수당, 0 원도 보낸다) · 「급여항목」(월 기본시간 · 월간 연장근무 · 기본시간 중 야간근무, 0.5 단위. 금액 = 시간 × 시급 × 배율 — 기본 1 · 연장 1.5 · 야간 0.5. 휴일근무 두 칸은 화면에서 뺐다) 표이고, 월급 = 급여항목 합계 + 비과세 합계다. 파트타이머는 따로 표를 두지 않고 소정근로시간 표에 근무시간(근무 · 휴게시간으로 셈한다) · 시급 · 소계 열과 소계 · 주휴수당(주 15시간 이상이면 주 시간 ÷ 40 × 8, 8시간까지) · 주급 · 월급여(주급 × 4.345) 줄을 붙이고 수당 · 월 근로시간은 숨기고 보내지 않는다(견본의 파트타이머 「수당」 줄은 저장할 칸이 정해지지 않아 뺐다). 계산은 `contract-form-model.ts` 의 `fullTimePay` · `partTimePay` · `monthlyWage`. 「계약서 조항」에 연차휴가 · 퇴직금 조항(기본 문구로 시작, 이어 쓰기에서 비워 둔 조항은 비운 채로 연다)이 있다. 같은 점포에 진행 중 계약이 있어 api 가 409 `CONTRACT_IN_PROGRESS` 를 주면 서버 액션이 그 목록을 돌려주고, 확인창(ConfirmDialog)이 대체할지 물어 `replaceContractIds` 를 실어 같은 본문을 다시 보낸다. 다른 점포 근무 시간 겹침(409 `WORK_TIME_OVERLAP`)은 api 문장을 그대로 보인다(다른 점포의 요일 · 시각은 싣지 않는다, CTR-26). 폼 로직은 `contract-form-model.ts` 에 두고 `pnpm test` 로 확인한다.

# API

whale-erp-api 를 호출한다. 주소는 `API_BASE_URL` 로 주입한다
(`.env.development` 는 `http://localhost:8000`, `.env.production` 은 비어 있고
배포 환경이 주입한다). 두 파일 모두 git 이 추적하지 않는다.

부르는 엔드포인트는 `GET /enums/{name}`(공개)과 `GET` · `POST` · `PUT` · `DELETE /contracts` · `GET /stores/options`(관리자 토큰)다. 점포 화면이 부르는 `/stores` 경로는 위 Layout 의 `src/app/stores/` 항목과 [점포 관리](/stores.md) 구현 절에 적는다. 근로계약의 요청 · 응답 타입은 `src/lib/api-types.generated.ts`(`pnpm openapi:types`)에서 가져온다(`contract-list.ts` 의 `ContractListItem` · `ContractListPage`, `contract-form-model.ts` 의 `CreateContractBody` · `ContractDetail`). `ApiError` 는 응답 본문(`body`)도 들고 있어 409 의 `code` · 목록을 화면이 쓴다. api 의 견본(items·stock_movements·staff·customers)과 견본 로그인
(`POST /auth/customer/login`, `GET /items`)은 2026-10-07 api 와 함께 지웠다(재영 결정).
관리자 웹 로그인은 1팀이 새로 만든다.

JWT 액세스 토큰은 `httpOnly` 세션 쿠키(`session`)에 담아 서버에서만 읽고, 매 호출에
`Authorization: Bearer` 로 싣는 틀은 남겨 두었다. 쿠키를 굽는 쪽은 새 로그인이 맡는다.
