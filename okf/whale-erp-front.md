안내한다. 플랫폼관리 바로가기는 ERP 탭이면 그 탭은 두고 플랫폼(`/platform`)을 새 탭(noopener)으로 연다 — 같은 탭을 플랫폼으로 바꾸면 앞서 본 ERP 화면이 뒤로 가기 기록에 남아 뒤로 갈 때마다 「접근 권한이 없는 메뉴」로 막혔다. 계정·메뉴(localStorage)는 바꾸지 않는다. 브라우저 탭 제목에는 BP 상호를 붙이지 정한다(`resolveTab`, `serviceOfPath`). 헤더 메뉴는 그 서비스의 메뉴(`serviceCode`)만 2단계까지(조회 권한이 없는 메뉴는 권한 있는 첫 하위 메뉴로 연결하고, 갈 곳이 없으면 빼며, 오른쪽 사용자 칸은 이름만 보인다 — 권한 이름은 2026-10-20 뺐다), 오른쪽 선택기는 ERP 면 점포 범위다(플랫폼 탭의 BP 선택기는 아직 없다). 범위를 바꾸면 지금 화면 메뉴(목록 · 상세 · 등록 · 수정, `usePageMenu`)의 목록으로 늘 가고 다른 검색 조건은 초기값이다(메뉴가 아닌 화면은 범위만 바뀐다, 2026-10-21 정책). 범위는 탭 안(sessionStorage)에만 있어 서버가 모르므로, 헤더가 메뉴로 갈 때(범위 변경 · 메뉴 링크) 짧은 값 하나 `?scope=ALL · DIRECT · FRANCHISE · STORE:12` 로 싣는다(`src/lib/store-scope.ts` 의 `withScope` — 메뉴 링크 · 범위 변경 모두 전체도 `scope=ALL` 로 적는다). 점포 번호는 1~9자리 양의 정수만 받는다. 어느 메뉴에 점포 검색 필터가 있는지 헤더는 모른다 — 메뉴 주소 · 코드는 환경마다 바뀔 수 있어 적어 두지 않는다. 필터가 있는 목록만 서버에서 `scope` 를 읽어 api 조건으로 바꾸고(직영 · 가맹 전체는 점포를 풀지 않고 점포유형으로, 점포 하나는 그 id), 없는 목록은 모르는 값이라 무시한다. 목록에서 사용자가 고른 점포는 그 목록 주소의 `storeIds` 에 두고 `scope` 보다 앞선다(목록에서 비운 「전체」는 빈 `storeIds=` — 쿼리 객체의 `storesCleared`). 헤더가 실어 온 전체(`scope=ALL`)와 목록에서 비운 전체는 다른 값이라, 헤더의 전체는 목록을 조작해도 `scope=ALL` 로 남아 뒤로 가기에 헤더가 따라온다. `scope` 는 늘 헤더 범위만 뜻해서, 주소에 `scope` 가 있으면 그 탭의 헤더 범위도 그 값으로 맞춘다(`admin-header.tsx` 의 `ScopeFromAddress` — 다른 탭에서 복사한 주소를 열 때. 그 탭의 점포에 없는 범위는 따르지 않는다). 상세 · 등록 · 수정을 오갈 때는 목록 주소를 `?back=` 으로 넘겨 그대로 돌아오고, 다른 메뉴로 갔다 헤더로 다시 들어오면 범위를 따른다. 점포 조건이 주소에 없으면(주소 직접 입력 · 즐겨찾기 · 그런 주소로 뒤로 가기) 필터가 범위로 채워 다시 검색한다. 전체도 `scope=ALL` 로 적으므로 헤더를 거친 기록 항목마다 범위가 남아, 뒤로 · 앞으로 가기에도 헤더가 주소를 따라온다(`scopeFromAddress`) — 전체를 빼던 때는 「전체로 메뉴에 들어옴 → 직영 → 뒤로」에서 헤더가 직영에 남고 필터가 다시 직영으로 채웠다. 서버가 고른 점포를 빼면 필터 칩도 서버 값으로 돌아오고(칩 동기화 키에 요청한 점포를 넣는다), 뺀 점포는 점포 고르기 후보에서 숨긴다(`droppedStoreIds` · `StorePicker` 의 `hidden` — 다시 고르면 같은 주소로 가 칩이 어긋난다). 필터가 다시 채울지는 주소에 점포 조건이 있는지로만 정한다 — 헤더 범위 변경에 반응하면 헤더의 이동을 덮는다. 범위의 점포 하나를 서버가 api 로 찾지 못하면 「전체」로 보고 「상단에서 고른 점포를 찾을 수 없어」로 안내하고(`keepFoundStores` · `resolveStoresQuery`), 주소의 범위를 그 탭에서 쓸 수 없으면(고를 점포가 없다 — `isUnusableScope`) 헤더는 따르지 않고 필터가 「전체」로 바꿔 토스트로 알린다. 헤더 범위(직영 · 가맹)와 고른 점포유형이 겹치지 않으면 빈 목록 · 엑셀 400 이 그 이유로 알린다(`scopeTypeMismatch`). 점포 조건 · 점포상태는 전용 함수(`withPickedStores` · `withScopeCondition` · `withStatuses`)로만 바꾸고 `withStoreFilter` 는 그 밖의 조건만 받는다. 직영 · 가맹 범위의 칩은 로그인 정보의 점포(폐점 제외)로 그리고 api 는 점포유형으로 거르므로, 로그인 뒤 생긴 점포나 「폐점」을 켰을 때의 폐점 점포는 목록에만 나온다(받아들인 차이). 등록 · 삭제 뒤 돌아갈 목록은 `withoutStoreSearch`(빈 `storeIds=` — 헤더 범위는 바꾸지 않는다)다. 탭 sessionStorage 의 `store-picks`(목록에서 고른 점포 기억)는 2026-10-21 에 없앴고 키는 로그아웃할 때 지우려고만 남겼다. 그 서비스의 홈이 아니고 그 서비스 메뉴에 없는 주소면 안내 후 `history.back()`(기록이 없으면 홈)이다 — 플랫폼 탭에서 ERP 주소로 왔으면(마지막으로 고른 BP 없이 즐겨찾기·주소 입력) * `src/app/(public)/(site)/signup/` - 로그인 전 실제 화면(1팀) 중 BP 회원가입 `/signup`(기본정보·사업자정보 인증(선택)·약관동의·제출)과 가입 완료 `/signup/done`. 로그인(`/login`)과 같은 로그인 전 틀(`(site)/layout.tsx` — `GuestHeader` · `GuestFooter`)을 쓰고, 모양은 ERP 디자인 시스템이 아니라 `docs/demo/src/pages/auth/signup.mjs`·`signup-done.mjs`(`design/guest/sign-up`(아래 항목)을 1팀이 옮긴 것)가 기준이다(2026-10-14~15. 폼 토큰은 `design/guest/guest-form.ts`·`theme.ts`를, 가입 완료는 `design/guest/guest-ui.tsx`의 `GuestPage`·`GuestVisual`·`GuestButton`을 그대로 가져다 쓴다). `auth-routes.ts` 의 공개 경로 `/signup` 아래라 로그인 없이 열린다. 처음엔 `/auth/signup` · `/auth/signup-done` 에 자체 GNB·푸터(`site-page.tsx`)와 로그인 대기 안내창(`login-pending.tsx`)을 두었으나, main 에 로그인과 공개 경로 목록이 들어와 이 자리로 옮기고 그 둘은 지웠다(2026-10-14). `src/app/design/guest/sign-up`(위 항목)과는 별개다: 저곳은 기획 시안을 옮긴 디자인 샘플(요청 안 보냄)이고, 이곳은 실제 API 를 부르는 운영 라우트다. 아이디·이메일은 칸을 벗어날 때 api 로 중복을 확인하고, 제출 전에 확인을 못 마친 칸을 다시 확인해 가입 요청이 중복으로 거절되지 않게 한다. 사업자정보 "인증하기"는 빈 칸과 사업자등록번호 형식(숫자 10자리, 숫자만 입력)을 먼저 보고, 통과하면 서버 액션 `verifyBusiness` 가 api `POST /auth/signup/business-verifications` 를 부른다 — api 가 번호 중복 → 국세청 진위확인을 하고 10분짜리 토큰을 준다. 확인하는 동안은 세 칸·버튼과 가입 버튼이 잠긴다. 토큰과 받은 시각은 화면 상태에만 두고, 가입할 때 `bizVerificationToken` 으로 싣는다. 세 칸이 비어 있으면 사업자정보 없이 가입하지만, 값이 있는데 인증이 없으면(재인증 · 10분 경과 · 가입 거절로 풀린 뒤 포함) 가입 요청을 보내지 않고 「인증하거나 지우기로 비운 뒤」 가입하게 한다(`bizSubmitBlock`) — 보이던 사업자정보가 조용히 빠진 채 가입되지 않게(PR #30 ⑤ 블로커). 받은 지 10분이 지났으면 가입 요청을 보내지 않고 인증을 풀어 다시 인증하게 하고, api 가 가입을 토큰 만료(400)나 사업자번호 중복(409)으로 거절해도 그 문구로 가려(`isBizSignupRejection`) 인증을 풀고 사업자정보 칸에 보인다. 진위확인 실패는 400 · 409 · 422(불일치) · 503(국세청 장애, 로그) 은 api 문구를, 429 · 그 밖은 정해진 문구를 보인다(`biz-verification.ts`). 불일치는 어느 칸이 틀렸는지 몰라 칸 테두리를 빨갛게 하지 않는다. 기본정보 칸은 아이디|이름, 비밀번호|확인, 이메일|연락처, 상호명 순이다(2026-10-13). 가입 완료 화면의 상호명·아이디·이메일은 가입 성공 뒤 서버 액션이 심는 httpOnly 쿠키(`signup-done-cookie.ts`, 10분, 경로는 `SIGNUP_DONE_PATH` 상수 `/signup/done`)로 받는다 — 쿠키가 없거나 깨졌으면 로그인으로 보낸다(명세 `S-UUBGOD`). 서버 액션은 사용자 IP 를 `X-Forwarded-For` 로 api 에 넘긴다 — api 의 IP 한도(가입은 도입문의와 같이 IP 당 1시간 5건)가 방문자별로 세어지려면 api `TRUST_PROXY` 에 이 서버가 있어야 하고, Next 앞에 `X-Forwarded-For` 를 덧붙이거나 덮어쓰는 프록시가 있어야 한다 — Next 는 이 머리말이 이미 있으면 그대로 두므로, 바로 노출되면 브라우저가 지어 보낸 IP 가 api 까지 간다. api 실패는(사업자정보 거절 400 · 409 는 위처럼 따로) 400 · 409 만 api 문구를 그대로 보이고 그 밖(429 · 404 · 5XX)은 정해진 문구로 보이며 서버 로그에 남긴다(`api-failure.ts`). 409 를 받으면 아이디 · 이메일을 다시 확인해 걸린 칸에 오류를 띄우고, 응답을 받았는지 알 수 없는 실패(10초 시간 초과 · 서버 액션 전송 실패)와 api 가 받은 뒤의 실패(응답 모양 · 완료 쿠키)는 「이미 가입되었을 수 있으니 로그인을 먼저 시도해 주세요」로 안내한다. 「웨일ERP 시작하기」는 비밀번호 없이 로그인한다(명세 [Auth](/auth.md)) — 서버 액션 `startSessionFromSignup` 이 완료 쿠키의 `signupToken`(10분, 폼에 싣지 않고 쿠키에서 읽자마자 지운다)으로 api `POST /auth/admin/signup-session` 을 불러 세션 쿠키를 굽고 권한 유형별 홈(`homeOf`)으로 간다. 이미 다른 계정으로 로그인돼 있으면 그 세션을 api 에서도 로그아웃한다. 토큰이 없거나(10분 경과 · 재사용) 거절되면 세션 쿠키까지 지우고 `/login` 으로 보낸다 — 남은 세션이 있으면 proxy 가 `/login` 을 옛 계정 홈으로 돌려보내기 때문이다. 완료 화면의 「로그인 화면」 글자 링크와 가입 화면의 「이미 계정이 있나요? 로그인」은 세션이 없으면 `/login`, 다른 계정 세션이 남아 있으면 그 계정의 홈으로 건다(머리말의 「홈으로」와 같은 이유). 관리자 웹 로그인은 아이디의 대소문자를 구분하고 api 는 가입 아이디를 소문자로 저장하므로, 아이디 칸은 입력하는 순간 소문자로 바꿔 보인다(`normalizeLoginId`) — 대문자로 친 그대로 두면 가입한 아이디를 그대로 쳐서는 로그인할 수 없다(PR #23 ⑤ 블로커). `(site)` 틀 전체가 `design/guest` 의 `GuestHeader`·`GuestFooter` 를 쓰고, 홈·`/login` 본문도 guest 디자인으로 바꿔 더는 두 디자인 시스템이 섞이지 않는다(2026-10-19 — 그 전의 `SiteNav`·`SiteFooter` 는 지웠다). 로그인한 채 열면 머리말의 Login 자리에 「홈으로」(자기 홈, `homeOf`)를 보인다 — `(site)/layout.tsx` 가 세션을 읽어 `GuestHeader` 에 넘기고, 디자인 샘플은 늘 Login 이다(main 의 PR #44 를 병합 때 옮김). 1720px 최소폭도 틀이 건다. 약관동의의 「내용보기」 팝업(`terms-dialog.tsx`)은 처음 열 때 api 시행 중 약관(`TERMS_SERVICE` · `PRIVACY_COLLECT`)을 받아 `TermsMarkdown` 으로 그린다 — 화면에 보인 버전과 동의 기록 버전이 같다. 목업 문구 사본(지운 파일)과 미정 값(`[ ]`) 빨간 표시는 지웠다(2026-10-19). 다른 화면(`stores`·`staff-members`)과 달리 이 폴더에만 있던 `_components/` 하위 폴더를 걷어 모든 파일을 `signup/` 바로 아래로 평평하게 옮겼다(2026-10-19) — 나머지 화면 폴더 전부가 하위 묶음 없이 평평한 구조다. 사용자 * `src/app/(public)/(site)/find/` - 아이디·비밀번호 찾기 `/find`(1팀, S-PHOPWY · S-EOMSRG). 틀(왼쪽 고래 그림)은 Figma 「아이디/비밀번호 찾기」 샘플과 같은 `design/guest/find-account/find-account-screen.tsx` 의 `GuestFindAccount` 이고, 제목 줄은 탭마다 안내 문구가 달라 폼이 `FindAccountHeading` 으로 그린다(ID 「회원가입 시 등록한 이름, 이메일 주소를 입력해 주세요.」 · 비밀번호 「…이름, 아이디, 이메일 주소를…」). 폼은 비로그인 폼 규격(`guest-form.ts`)이고 칸은 시안의 휴대폰 인증 대신 정책대로 이름 · 이메일(비밀번호 탭은 아이디까지)이다. 고객센터 안내 카드는 연락처가 정해지지 않아 두지 않는다(2026-10-19 재영). 탭은 해시 `#id` · `#pw` 로 고르고(서버는 해시를 몰라 첫 렌더는 ID 탭, 붙은 뒤 `hashchange` 까지 따른다. 탭을 바꾸면 `replaceState` 로 해시만 바꾼다), 버튼 줄은 시안의 주 동작 · 회원가입 · 로그인 이동이다. 아이디 탭은 `POST /auth/admin/login-id-find-attempts`, 비밀번호 탭은 `POST /auth/admin/temporary-passwords` (본문을 쓰지 않아 `requestRaw` 로 상태 코드만 본다)다. 실패 판정은 next 를 불러오지 않는 `find-failure.ts` 에 두고 `find-failure.test.ts` 로 검사한다 — 일치 없음은 api(Nest) 가 직접 준 404(본문 `statusCode` 404, 「Cannot 」으로 시작하지 않음)일 때만이고 문구는 탭마다 화면이 정한다(`failureOf(e, notFound)`). 라우트가 없는 404 · 게이트웨이의 HTML 404 는 연결 문구와 서버 로그다. api 문구를 그대로 보이는 것은 1시간 5회 초과(429, 한글)뿐이고, 스로틀러 429 는 「요청이 많습니다」, 400 은 「입력한 이메일 형식을 확인해 주세요」(브라우저는 `a@b` 를 통과시키지만 api 는 영어 문구로 거절), 그 밖은 연결 문구와 로그다. 임시 비밀번호는 메일 발송 오류(503 + `TEMPORARY_PASSWORD_SEND_FAILED`)면 「메일 발송을 확인하지 못했습니다. 몇 분 안에 메일이 오지 않으면 다시 요청」, 그 밖의 5xx 는 「처리 결과를 확인하지 못했다」, 10초 시간 초과는 발송 안내다. api #77 머지 전에는 일치 여부와 상관없이 202 라 늘 발송 안내다. 아이디 탭은 10초 초과 · 5xx 도 연결 문구다. 로그인한 채 `/find` 에 오면 `proxy.ts` 가 권한별 홈으로 보낸다. 두 서버 액션은 회원가입과 같은 `src/lib/forwarded-headers.ts` 의 `apiHeaders()` 로 사용자 IP 를 `X-Forwarded-For` 로 넘긴다 — 넘기지 않으면 api 요청 제한이 Next 서버 주소 하나로 센다.

# API

whale-erp-api 를 호출한다. 주소는 `API_BASE_URL` 로 주입한다
(`.env.development` 는 `http://localhost:8000`, `.env.production` 은 비어 있고
배포 환경이 주입한다). 두 파일 모두 git 이 추적하지 않는다.

회원가입은 `POST /auth/signup`(가입, 중복이면 409), `POST /auth/signup/login-id-availability`·`POST /auth/signup/email-availability`(중복 확인, `{ available }`) 셋을 부른다 — api PR #37(bulbasaur 브랜치)에서 들어온다. 사업자정보 진위확인 `POST /auth/signup/business-verifications`(`{ verificationToken }`, 10분)와 가입의 `bizVerificationToken` 은 api lapras 브랜치(#37 위)에서 들어온다.
지금 부르는 엔드포인트는 `POST /auth/admin/login`·`/auth/admin/refresh`·`/auth/admin/logout`·`/auth/admin/password-change`(서버에서만), 그리고 BFF `src/app/api/[...path]/route.ts`(GET 만, 쿠키의 토큰을 붙여 대신 부르고 api 401 이면 세션 쿠키를 지운다)를 거쳐 화면이 부르는 `GET /auth/admin/login-info`(로그인마다 첫 탭에서 한 번)·`/bp-codes/{bpCodeId}/stores`·`/bp-codes/{bpCodeId}/code-items`(플랫폼 계정이 고른 다른 BP 의 탭)다. GNB 「내정보 관리」(MY PAGE, F-AMTDCK > S-JXKHCM)는 `src/lib/my-profile.ts`에서 `GET`·`PATCH /auth/admin/me`·`GET /auth/admin/me/email-availability`를 부른다 — 항상 `CurrentUser()`의 로그인 계정 자신만 보고 고치며, BP 선택(`/bp-switch`)으로 보고 있는 BP 는 건드리지 않는다. 저장은 조회 응답의 `updatedAt`을 함께 보낸다 — platform-admins 수정과 같은 동시 수정 검사(ip-code-review-claude 적대적 리뷰로 찾음, 2026-10-21)라, 저장 뒤 204 응답엔 새 `updatedAt`이 없어 다시 조회해 받는다(`my-page-panel.tsx`). 이메일을 바꿀 때만 「지금 비밀번호」 칸이 폼에 나타나 `currentPassword`로 함께 싣는다 — 탈취한 접근 토큰만으로 로그인 이메일을 공격자 주소로 바꿔 비밀번호 찾기를 가로채는 계정 탈취를 막는다(같은 리뷰로 찾음, my-profile(직원 앱) email-change 와 같은 통제). api 경로는 있지만 아직 `openapi.json`에 실리지 않아 타입은 손으로 적었다(`src/lib/my-profile-form.ts`가 검사·변환). api 의 견본(items·stock_movements·staff·customers)과 견본 로그인
3팀 화면(main)이 서버 컴포넌트·서버 액션에서 부르는 엔드포인트는 `GET /enums/{name}`(공개)과 `GET` · `POST` · `PUT` · `DELETE /contracts` · `GET /stores/options`(관리자 토큰)다. 점포 화면이 부르는 `/stores` 경로는 위 Layout 의 `src/app/stores/` 항목과 [점포 관리](/stores.md) 구현 절에 적는다. 근로계약의 요청 · 응답 타입은 `src/lib/api-types.generated.ts`(`pnpm openapi:types`)에서 가져온다(`contract-list.ts` 의 `ContractListItem` · `ContractListPage`, `contract-form-model.ts` 의 `CreateContractBody` · `ContractDetail`). `ApiError` 는 응답 본문(`body`)도 들고 있어 409 의 `code` · 목록을 화면이 쓴다. api 의 견본(items·stock_movements·staff·customers)과 견본 로그인
(`POST /auth/customer/login`, `GET /items`)은 2026-10-07 api 와 함께 지웠다(재영 결정).
JWT 액세스 토큰은 `httpOnly` 세션 쿠키(`session`)에 담아 서버에서만 읽고, 매 호출에
`Authorization: Bearer` 로 싣는다. 쿠키는 로그인 서버 액션과 `proxy.ts` 의 갱신이 굽는다.
아직 없는 것: 세션 만료 경고창. 로그인 이력에는 브라우저가 아니라 Next 서버의 IP 가 남는다.

```bash
pnpm openapi:types  # api openapi.json → src/lib/api-types.generated.ts
```
