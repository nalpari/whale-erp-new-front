# What it is

근무스케줄 관리(`/work-schedules`, 메뉴 MN000010 「근무스케줄 관리」 — #202 · #343 · #608). 목업 `docs/mockup/staff/index.html` 근무스케줄 탭과
데모 `docs/demo/staff/work-schedules.html`(원본 `docs/demo/src/staff-sections.mjs` 의 `schedTab` · `staff-parts.mjs` 의 `schedWeek` · `schedMonth` · `coverRow` · `weekNav`)을 공통 컴포넌트로 옮겼다.
2026-10-22 재영 지적으로 배치를 데모에 다시 맞췄다: 카드 하나(`detailBody` 틀, 간격 24) 안에 첫 줄 근무지 선택칸 · ‹ 「2026년 10-19 ~ 10-25」 › · 날짜 고르기 칸 · 「이번 주」 | 「지난 주 복사」(soft) · 「근무스케줄 등록」, 둘째 줄 주간 · 월간 전환(데모 segment — 회색 바탕 · 굵게), 근무표, 변경 이력. 날짜 고르기 칸과 「이번 주」는 데모에 없지만 남긴다(재영). 「00~24시 · 근무일은 시작한 날」 안내는 뺐다.
2026-11-05 사용자 지정(3팀 확인 필요)으로 도구 줄을 다시 짰다: 첫 줄은 보기 전환(아이콘 + 글자 — 주간 가로 막대 · 월간 달력)만, 둘째 줄은 「근무지」 라벨 + 선택칸 300px(220 → 300, 점포명이 길다) · 기간 이동 · 오른쪽 끝 「지난 주 복사」(soft) · 「근무스케줄 등록」. 주간 기간 이동은 ‹ 「2026년 11월 2일 ~ 8일」 › · 「이번 주」(`weekRangeLabel` — 달이 바뀌면 「2026년 10월 26일 ~ 11월 1일」, 해가 바뀌면 끝에도 연도. 전엔 「2026년 11-02 ~ 11-08」), 월간은 ‹ 「2026년 11월」 › · 「이번 달」 — 「이번 주」 · 「이번 달」은 outline(전엔 off). 날짜 고르기 칸(`WeekJump`)은 그대로다.
점포가 하나도 없어도 같은 틀(제목 줄 · 도구 줄 · 보기 전환)을 그리고, 근무지는 「선택」 하나뿐인 칸, 근무표 자리 가운데에 「등록된 점포가 없습니다.」(BP 마스터 · 플랫폼) / 「담당 점포가 없습니다.」(그 밖) + 회색 둘째 줄 「점포를 등록하면 …」 / 「점포를 배정받으면 직원의 근무스케줄을 등록하고 관리할 수 있습니다.」(`ScheduleNoStore`, 전엔 왼쪽 위 한 줄 「관리하는 점포가 없습니다.」만). 점포가 있는데 주소에 없으면 첫 점포로 옮기는 동안 「점포를 불러오는 중입니다.」.
화면 주소는 탭 BP 주소 `/bp/{bpCodeId}/work-schedules` 다(`BP_PATH_SCREENS`) — 플랫폼 계정은 고른 BP 의 근무스케줄만 본다. 보기 전환 · 주/달 이동 ·
근무표의 날 링크(서버)는 `screenPath()` 로 만든 바탕(`hrefBase`)에, 근무지 · 날짜 고르기 · 이력 조작(클라이언트)은 `bpPath` 로 탭 BP 를 붙인다. 목록
조회가 api 거절(BP 를 고르지 않은 플랫폼 계정 400 · 다른 BP 403)을 받으면 그 문장을 보이고(`deniedMessageOf`), 업무 범위 밖 점포 404 는 그대로
`notFound()` 다. 처리 뒤 `revalidatePath("/work-schedules")` 는 rewrite 의 목적지(폴더) 경로라 그대로 둔다.
계획은 `docs/plans/2026-10-21-work-schedules-screen.md`, api 결정은 api `docs/plans/2026-10-21-work-schedules.md` 다.

화면 상태는 주소에만 둔다: `?store=&view=week|month&week=<월요일>&day=&month=YYYY-MM&hfrom=&hto=&hstaff=&hpage=&hsize=&copy=1`. 기본값(이번 주 · 오늘 · 이번 달 · 이력 1쪽 · 20건)은 주소에서 뺀다. 옛 주소의 `history=1` 은 읽지 않는다(이력은 늘 보인다).
근무스케줄은 점포 하나씩 본다 — 주소에 점포가 없으면 헤더 범위가 점포 하나일 때 그 점포(`?scope=STORE:12` 도 읽는다), 아니면 폐점이 아닌 첫 점포로 옮긴다(`SchedulePicker`).

# 주간 보기

* 요일 칩 7개(월~일, 그날 근무 인원 `days[].headcount`) → 고른 요일의 시간축 24칸(00~23시).
* 직원 줄은 그날 `schedulableDates` 에 든 직원만(휴무 포함, STAFF-29). 본사에게 가려진 직원(`isMasked`)은 줄을 두되 이름 · 막대를 비우고 key 는 순번이다(STAFF-39).
* 막대는 시작 · 길이의 비율, 자정을 넘으면 24시에서 자르고 글자로 「22:00~익일 02:00」(STAFF-33), 24시에 끝나면 「~24:00」. 쪼갠 근무는 한 줄에 막대 여럿.
* 근무 인원 줄 24칸 — api 의 30분 칸 48개에서 **한 시간 칸 = 두 반칸 중 작은 값**(30분 공백도 0 으로 보이게). api 가 전날 넘어온 새벽 근무도 센다(api Q4). 근무 앞뒤 · 사이 모두 빈칸 없이 숫자로 보이고 아무도 없으면 0(빨강)이다(2026-10-22 재영 — 앞서 둔 「근무 바깥은 빈칸」을 바꿈). 공백 안내는 그날 시작한 근무의 첫 시작~마지막 종료 사이만 세고(STAFF-37), 전날에서 넘어온 근무가 끝난 뒤의 새벽은 공백으로 세지 않는다. 그래서 주간은 전주 일요일부터 8일을 받는다. 가린 직원의 넘어온 근무는 items 에 없어 그날 근무로 센다. 0 빨강 · 1 회색 · 2 이상 파랑 + 숫자.
* 공백 줄 — 데모 gapBar 처럼 근무 인원 줄 바로 아래(범례 위)에 테두리 없이 한 줄. 그날 시작한 근무의 첫 시작~마지막 종료 사이 0 인 구간을 30분 단위로 빨강 배지 「공백 1시간 30분」 + 「15:00-16:30 에 배정된 직원이 없습니다.」(없으면 파랑 「공백 없음」). 오른쪽 끝 soft 버튼 「이 시간대에 배정」이 그 근무일 · 공백 시각으로 등록 패널을 연다 — 공백이 여럿이면 버튼마다 「15:00-16:30 배정」으로 시각을 적는다.
* 범례(아무도 없음 · 혼자 근무 · 휴게 불가 · 2명 이상)는 맨 아래. 색 칸 14px + 같은 계열 테두리, 글자 14px(전엔 12px 칸 · 13px 글자, 2026-11-05 사용자 지정, 3팀 확인 필요).
* 그날 근무 가능한 직원이 없으면 표 자리 가운데 「근무 가능한 직원이 없습니다.」(지난 날 보기 전용이면 「이날 근무가 없습니다.」, 전엔 왼쪽 위, 2026-11-05 사용자 지정, 3팀 확인 필요).

* 여는 곳: 도구 줄 「근무스케줄 등록」(등록 권한 — 플랫폼 계정은 권한이 없어도 버튼을 두고 누르면 「접근 권한이 없습니다.」 토스트, 2026-11-05 사용자 지정, 3팀 확인 필요) · 막대(수정 권한이 없으면 글자만) · 「이 시간대에 배정」. 패널(`SchedulePanel`)은 화면 안 상태라 주소에 남지 않는다 — 입력이 이동에 지워지지 않게. 패널은 바탕창을 깔고 바탕을 누르면 닫는다 — 패널이 아닌 본문(제목 줄 포함)은 그동안 inert(출퇴근 대신 등록과 같다, 2026-11-05 사용자 지정, 3팀 확인 필요 — 전엔 바깥을 눌러도 닫히지 않았다). 안쪽 여백은 패널 것(24 · 칸 사이 16)만 쓴다.
* 묶음 제목 「근무스케줄 정보」, 칸 순서는 등록 인원(라디오 「1명 · 여러 명」, 필수, 수정에는 없음) → 근무일 → 직원 → 시간, 칸 묶음 사이 24(2026-11-05 사용자 지정, 3팀 확인 필요 — 전엔 묶음 「근무」, 라디오 「한 명 · 여러 명 일괄」이 제목 아래). 근무일은 하루 하나. 직원은 그 근무일에 받을 수 있는 직원(`GET /assignable-staff`, STAFF-29)이고 근무일을 바꾸면 고른 직원을 비운다. 선택지 「선택」, 없으면 「근무 가능한 직원이 없습니다」, 상태 문구(없음 · 불러오는 중)는 14px 회색(전엔 12px).
* 등록 인원 · 근무일 · 직원을 바꾸면 지난 저장 실패 문장(겹침 등)과 칸 오류를 내린다 — 1명에서 거절된 뒤 여러 명으로 바꾸면 그 문장과 「직원을 한 명 이상 골라 주세요.」가 함께 보였다(2026-11-05 사용자 지적).
* 직원마다 상자 — 회색 머리 줄(42px)에 이름과 「근로계약 시간적용」(26px · 13px outline 모양, 계약에 시작 · 종료가 있을 때만, STAFF-14), 아래에 시작시간 · 종료시간 · 휴게. 1명 · 수정도 같은 상자이고 아직 고르지 않았으면 머리 줄에 회색 「직원을 고르면 근무시간을 입력할 수 있습니다.」(2026-11-05 사용자 지정, 3팀 확인 필요 — 전엔 off 34px 「계약 값으로 되돌리기」, 라벨 「시작 · 종료」). 직원을 고르면 계약 근무시간(`GET /defaults`)으로 채운다. 공백에서 열면 그 시각 · 휴게 0분을 두고 계약 값으로 덮지 않는다.
* 시각은 30분 단위 선택(시작 00:00~23:30, 종료 00:30~24:00 — 시작보다 이르면 「익일 02:00」), 휴게는 분. 화면에서 먼저 막는 것은 빈칸 · 24시간 · 휴게 ≥ 근무시간이고 나머지(계약 · 퇴직일 · 겹침 · 가입 전 · 가림)는 api 문장을 그대로 보인다.
* 여러 명은 체크 목록 → 직원마다 상자, 저장은 `POST /bulk`. 일부가 실패하면 성공한 직원은 빼고 실패한 직원만 사유와 함께 남긴다.

* 버튼 줄은 가운데 [취소] [삭제](soft, 수정 · 삭제 권한) [저장] — 1명 · 여러 명 · 수정 모두 「저장」(전엔 삭제가 왼쪽 끝 · 나머지 오른쪽 끝, 여러 명은 「n명 등록」).
* 칸 오류 문구는 그 칸 바로 아래에 붙인다 — 한 명 등록의 시간 오류는 시간 칸과 6px 한 묶음, 일괄의 「직원을 한 명 이상 골라 주세요」는 고른 직원 줄 뒤가 아니라 직원 체크 칸 바로 아래다(직원 목록을 불러오는 중 · 실패면 이 문구는 안 보이고 저장은 그대로 막힌다, 2026-11-04 사용자 지정).
* 수정은 직원 고정, 근무일 · 시각 · 휴게. 「삭제」는 확인창 뒤(삭제 권한). 결과를 모르면(5xx · 끊김) 토스트로 알리고 화면을 새로 받아 닫는다 — 다시 저장하면 겹칠 수 있다.
