# What it is

관리자 웹 「직원관리 › 출·퇴근 현황 조회」(메뉴 `/attendance-records`, MN000025, WHALEERP-219). 데모 `docs/demo/staff/attendance.html`
(staff-sections.mjs attendFilter · attendTab)을 공통 컴포넌트로 옮겼다. 메뉴 표시는 메뉴 권한이, 업무 범위 · 본사 제공 동의 가림은 api 가 본다.
화면 주소는 탭 BP 주소 `/bp/{bpCodeId}/attendance-records` 다(`BP_PATH_SCREENS`, WHALEERP-637) — 플랫폼 계정은 고른 BP 의 기록만 본다. 필터 이동은
`bpPath`, 날짜 · 주 이동 링크(서버)는 `screenPath()` 로 탭 BP 를 붙이고, 보정 기간은 지금 주소(`usePathname`)를 그대로 쓴다. 보정 뒤
`revalidatePath` 는 폴더 경로 그대로다. api 거절(BP 400 · 403 · 404, `deniedMessageOf`)은 오류 화면이 아니라 그 문장을 보인다.

# Layout

- **필터 7개**(STAFF-31, 2026-10-08 재영): 점포 · 직원(이름 또는 번호) · 고용형태 · 출퇴근 상태(여섯, 기본 모두) · 확인 필요 사유 · 기록 구분(직원
  등록 · 대신 등록 · 보정됨) · 재직 상태(기본 재직). 주소에만 두고 유지하지 않는다. 점포는 TO-DO 목록과 같은 점포 고르기 · 헤더 범위 채우기
  (데모의 「점포명」 검색칸 대신). 확인 필요 사유는 넷(반경 밖 출근 · 반경 밖 퇴근 · 위치 조작 감지, ATT-11 · 2026-10-26 재영, 근무 12시간 초과 — 출근부터 12시간 넘은 직원 퇴근, 2026-10-27 재영). 데모 · 목업은 앞의 셋이다. 옛 값 「위치 오차 초과」만 남은 줄은 사유 거르기에 걸리지 않는다(2026-10-23 사용자 결정). 직원은 급여명세서에서 열면 직원 레코드(`staffMemberId`)로 좁히고 재직 상태는 전체로 연다 — 직원 칸을 고치면 풀린다. 사유 · 기록 구분은 그 값이 있는 줄에만 건다.
- **두 칸**(일별 출퇴근 · 근태 요약): 사이 36px(DESIGN.md 간격 예외 — 24px 는 왼쪽 표 끝과 「근태 요약」이 붙어 보였다), 두 칸 높이를 같게 한다(2026-11-05 사용자 지정, 3팀 확인 필요).
- **일별 출퇴근**(왼쪽 칸): 머리 오른쪽 ‹ 날 ›(「11월 4일 (화)」). 표 틀이 옆 근태 요약 아래 끝까지 늘어나 두 칸의 아래 선이 맞는다 — 줄은 위에서부터 쌓이고 남는 높이는 틀 안 빈칸이다. 비면 열 이름 줄 아래 빈 칸 가운데 「출·퇴근 기록이 없습니다.」(DataTable `fillEmpty`, 2026-11-05 사용자 지정, 3팀 확인 필요). 직원 · 예정(시작 시각) · 출근 · 퇴근 · 비고(상태 꼬리표). 퇴근 없음은 아직 퇴근을 기다리는 날 「근무 중」,
  api 가 퇴근 미등록으로 준 날 「미기록」 — 퇴근은 다음 날까지 받으므로 어제 출근은 근무스케줄이 자정 전에 끝났을 때만 퇴근 미등록이다(밤샘 근무). 점포가 둘 이상 섞이면 직원 이름 옆에 점포 이름을 옅게 붙인다(데모에 없음).
- **근태 요약**(오른쪽 칸): 머리 오른쪽 ‹ 주 ›(「11월 2일 ~ 11월 8일」 — 일별 칸과 같은 「N월 N일」 표기, `monthDayLabel`, 전엔 「11-02 ~ 11-08」). 막대 줄 라벨은 13px 들여 아래 근로시간 표 라벨과 시작선을 맞추고 굵기도 표 라벨과 같은 500, 라벨 98px 이라 막대가 표 값과 같은 세로줄(123px)에서 시작한다(2026-11-05 사용자 지정, 3팀 확인 필요). 라벨 앞에 근무스케줄 범례와 같은 14px 색 칸(옅은 바탕 + 같은 계열 테두리 — 정상 파랑 · 지각 노랑 · 미기록 빨강), 막대 채움도 같은 계열 진한 색이다(전엔 셋 다 회청, 2026-11-05 사용자 지정, 3팀 확인 필요). 정상 출근 · 지각 · 미기록(미출근 · 출근 미등록 · 퇴근 미등록) 막대와 횟수, 근로시간 표(총
  근로시간 · 연장 · 주휴 대상은 api 기간 조회가 한 주일 때 주는 직원별 값 `weekStaff` — 급여 계산(227)과 같은 규칙: 근무는 휴게(근무스케줄,
  없으면 계약)를 뺀 시간, 연장은 정직원 하루 8시간 · 주 40시간 초과 · 파트타이머 계약 요일 시간 초과, 주휴 대상은 1주 소정근로시간 15시간
  이상이고 계약 요일 개근. 거른 줄에 남은 직원만 더한다. 야간 = 22~06시는 급여 계산에 없어 화면이 센다(2026-10-23 사용자 결정).
  점포 · 고용형태 · 재직 상태만 걸린다.
- **보정이 필요한 기록**(아래): 머리 오른쪽 기간(기본 한 달, 92일 이하, 오늘까지). 비면 열 이름 줄은 두고 빈 칸이 본문 남는 높이를 채워 가운데 「보정이 필요한 출·퇴근 기록이 없습니다.」(기간이 늘 걸려 있어 문구는 하나, 2026-11-05 사용자 지정, 3팀 확인 필요). 퇴근 · 출근 미등록, 확인 필요 사유, 수정됨, 대신 등록 줄.
  머리에 「출퇴근 대신 등록」(등록 권한 — 그날 서명 완료 계약이 있는 직원이 선택지. 위치정보에 동의한 직원은 「(보정)」이 붙고, 출근 · 퇴근을
  모두 안 찍은 날만 두 시각을 함께 넣어 보정으로 채운다 — 퇴근 필수, 버튼 · 알림도 「보정」, api `isProxy`, 2026-10-26 재영), 줄마다 「보정」 · 「이상 없음」(수정 권한, 최근 3개월만,
  WHALEERP-220) · 「이력」(보정 · 대신 등록한 줄). 보정 · 대신 등록은 오른쪽 패널(출근 · 퇴근 HH:mm, 사유 필수, 원본 시각 옆에), 「이상 없음」은
  확인창, 이력은 창(일시 · 구분 · 처리한 사람 · 변경 전후 · 사유). 급여명세서가 확정된 기간이면 패널과 저장 결과에 경고, 그사이 다른 관리자가
  고쳤으면(409) 알리고 최신 기록을 다시 받는다. 대신 등록 패널은 퇴근이 출근보다 이르거나 같으면 다음 날 퇴근이라 그때 「다음 날(10/24) 02:00
  퇴근으로 저장합니다」를 실제 날짜로 보인다(`overnightNote`). 보정 패널은 출근이 있는 짝이면 「다음 날 퇴근」 체크로 퇴근 날을 api 에 늘 보낸다
  (`checkOutNextDay` — 퇴근을 출근 다음 날까지 받아 24시간 넘는 짝이 있어 시각만으로는 날을 알 수 없다, PR #159 리뷰). 처음 값은 원래 퇴근이
  출근한 날 뒤인가(`initialNextDay`), 퇴근이 출근보다 이르거나 같으면 체크가 고정된다(`forcedNextDay`). 원본 퇴근 · 고칠 기록 선택지에는
  「(다음날)」 · 「(+N일)」을 붙인다(`laterDayMark`). 저장할 날은 `fixSaveNote` 로 — 「다음 날(10/24) 09:30 퇴근으로 저장합니다」, 출근 없는
  퇴근에 밤 출근을 채우면 「전날(10/23) 22:00 출근으로 저장합니다」(api 가 출근을 전날로 둔다). 패널 아래 안내 박스(`GuideBand` 「보정 안내」)도 짝에 맞춘다 — 최근 3개월 · 미래 시각 불가, 직원 근무 앱 연필 아이콘, 확인 필요 표시 · 사유 삭제, 끝에 출근이 있으면 「퇴근 시각이 출근 시각과 같거나 이전인 경우, 다음 날 퇴근한 것으로 처리됩니다.」 · 「그 외에 다음 날 퇴근한 경우, 관리자가 「다음 날 퇴근」을 체크합니다.」, 출근 미등록 줄이면 「출근 시각이 퇴근 시각과 같거나 이후인 경우, 전날 출근한 것으로 처리됩니다.」. 아직 오지 않은 시각은 api 가 400 으로 막고 그 문장을 패널에 보인다.
  대신 등록 패널의 직원 선택지는 열 때 한 번, 날짜를 바꿀 때마다 다시 받는다(늦게 온 앞 날짜 응답은 버린다).
- **보정 · 대신 등록 패널 모양**(2026-11-05 사용자 지정, 3팀 확인 필요): 바탕창을 깔고 바탕을 누르면 닫는다 — 패널이 아닌 본문(제목 줄 · 필터 · 두 칸 · 표 · 기간)은 그동안 inert(`BackdropInert`). 패널 안 여백은 패널 것(24 · 칸 사이 16)만 써 BP 마스터 등록과 같은 폭 · 간격. 안내는 묶음 상자 밖 아래 안내 박스(`GuideBand`, 전엔 상자 안 13px 회색), 버튼은 가운데 [취소] [저장](전엔 오른쪽 끝, 「보정 저장」 · 「대신 등록」 · 「보정」). 사유 칸은 2줄(전엔 4).
  대신 등록: 직원 칸이 한 줄 전체 폭(「이름 · 점포 (보정)」 선택지가 넘치지 않게), 그 아래 줄 날짜. 선택지 첫 줄은 「선택」(불러오는 동안만 「불러오는 중…」, 전엔 「직원 선택」 · 「등록할 수 있는 직원 없음」). 안내 박스 「대신 등록 안내」 네 줄 — 위치정보 수집에 동의하지 않았거나 수집을 중지한 직원은 관리자가 대신 등록 · 최근 3개월 이내만, 미래 시각 불가 · 직원 근무 앱 연필 아이콘 · 퇴근이 출근과 같거나 이전이면 다음 날 퇴근.
  「다음 날(10/24) 02:00 퇴근으로 저장합니다」(`overnightNote`)는 칸 오류와 같은 빨강 13px(전엔 먹색 500, 막지는 않는다).
  저장 실패 문장(api 4xx)은 출근 · 퇴근을 고치면 내리고, 대신 등록은 직원을 바꿔도 내린다. 단 미래 시각 거절이었으면 저장할 순간이 모두 지금 이전이 될 때만 내린다(`hasFutureTime` · `proxyPoints` · `fixPoints` — api 와 같은 다음 날 · 전날 규칙으로 순간을 만든다. 새 오류를 띄우지는 않는다).
- 데모 · 목업과 맞춘 것(2026-10-23): 「수정됨」 · 「대신 등록」 꼬리표 옆에 가장 최근 그 이력의 「08-30 정하윤」 · 「위치 수집 일시 중지 · 정하윤」
  (`editTail`, api 기간 줄의 `edits`), 이력 창의 처리한 사람 「정하윤 (BP 마스터)」(`byLabel`), 기록 보정의 원본 시각은 칸 아래 도움말,
  출근 · 퇴근은 시각 칸(`type="time"`), 대신 등록은 직원 · 날짜 순. 일별 출퇴근의 지각은 「지각 18분」(목업, `lateMinutes`), 미출근은 출근
  칸에 「미기록」(데모).
- 빈 퇴근은 퇴근 미등록 줄만 근무스케줄 종료 시각으로 채운다.
- 보정이 필요한 기록의 기간은 최근 3개월 안 · 오늘까지로 묶는다(목업 「최근 3개월 안 · 이 안에서만 수정 가능」) — 주소로 그 밖이 와도 줄인다.
- 확정 · 발송된 급여명세서 기간 경고는 보정 패널 · 이상 없음 확인창 · 대신 등록 패널(고른 직원의 그 날, api `proxy-staff` 의 `isPayslipConfirmed`)에
  저장 전에 보이고, 저장 뒤 토스트로도 알린다(218).
- 일별 출퇴근 비고에 확인 필요 사유가 남은 기록은 「확인 필요 · 반경 밖 출근」 꼬리표를 덧붙인다(데모에 없음 — 2026-10-23 재영: 비고의 꼬리표만
  남기고 예정 시간 범위 · 번호 끝 4자리 · 상태별 인원 줄은 데모대로 뺀다).
- 데모 그대로 둔 것: 「수정됨」 · 「대신 등록」만 있는 줄은 「이력」만 있다(보정 없음). 「이상 없음」은 확인 필요 사유가 있는 줄에만 — 데모는
  출근 · 퇴근 미등록 줄에도 두지만 미등록은 기록에서 나오는 상태라 지울 사유가 없다(정책 확인 대기). 목업의 「퇴근 시각 이상」 사유는
  만들지 않는다(2026-10-26 재영).
