* 사업자 진위확인은 api 연동 전이라 503 을 칸 아래에 보인다
* 결과를 모를 때(503 을 뺀 5xx · 연결 끊김 · 응답을 못 읽음): 등록은 「목록에서 확인」을 안내하고 저장을 잠근다(다시 저장하면 둘이 생길 수 있다). 수정은 최신 정보를 다시 받아 바뀌었으면 저장된 것으로 본다. 삭제는 목록으로 보내고 알린다
* 등록 BP: 이 탭의 BP 를 싣는다 — BP 계정은 소속 BP 다. 플랫폼 계정은 BP 를 고른 탭에서만 점포 메뉴(ERP)가 열린다 — 서비스 바로가기의 웨일ERP 로 BP 를 골라 연 새 탭(`/bp-switch`)의 점포관리에서 등록하면 그 탭의 BP 로 등록된다(2026-10-19. 환경 변수 `STORE_REGISTER_BP_CODE_ID` 는 2026-10-15 에 걷었다). 화면 버튼은 지금 주소(/stores 와 그 아래 등록 · 수정)의 메뉴 권한(`usePagePermission`, 메뉴 코드를 적지 않는다)으로 보이고, 막는 것은 api 다
* 목록 필터의 점포 고르기는 헤더 점포 범위를 따른다 — 범위를 바꾸면 이 메뉴 화면(목록 · 상세 · 등록 · 수정)에서 목록으로 가서 범위의 점포로 검색하고, 헤더 메뉴 링크로 들어와도 같다. 전체는 조건 없이, 직영 · 가맹은 그 유형 점포 모두(1000개까지). 목록에서 바꾼 점포는 이 목록에만 쓴다. 등록 · 삭제 뒤 목록은 점포 검색이 「전체」다 — 수정은 유지한다(2026-10-20)
* 상태만 바꾸는 저장(상세 [상태 변경])은 상세 값을 그대로 다시 보내는 왕복이다 — 빈 사업자주소 · 층 구분만 있는 줄 · 화면이 모르는 층 구분도 바꾸지 않고 돌려보낸다
* 화면 코드는 [Whale ERP Frontend](/whale-erp-front.md) 의 `src/app/stores/` 항목

# 구현 (2026-10-19)

* 변경 이력은 상세에 늘 펼쳐 보이던 표 대신, 기본정보의 [변경이력] 버튼으로 여는 팝업이다. 등록 · 최종수정 한 줄은 기본정보 쪽에 그대로 남는다
* 점포유형 큰 선택 카드는 등록 화면에만 보인다. 수정 화면은 등록 뒤 바꿀 수 없는 값이라 카드를 보이지 않고, 제목 줄에 점포코드 · 점포유형만 적는다
* 좌표(위도 · 경도) 줄에 [주소로 다시 계산] 버튼을 등록 · 수정 화면 모두에 둔다 — 주소를 고르면 좌표가 자동으로 채워지지만 그 뒤 직접 고칠 수 있어, 고친 값을 주소 기준 값으로 되돌리는 용도다. 지금 입력된 점포 주소(괄호 속 참고항목은 떼고)로 다시 묻고, 실패해도 이미 있던 좌표는 지우지 않는다
* 위도 · 경도 입력칸은 숫자 · 마침표 · 마이너스만 받는다
* 사업자정보 인증 버튼 문구는 인증 전 "지우기"(아직 확정된 값이 없어 비운다)와 인증 후 "사용안함"(받아 둔 인증을 안 쓰기로 한다)으로 가른다. "인증완료" 표시는 사업자정보 묶음 제목 한 곳에만 둔다
* 점포 주소를 지우면 좌표뿐 아니라 위치 적용 여부도 미사용으로 되돌린다 — 지운 주소 기준의 좌표를 쓴 채로 남지 않게 한다
* 점포상태 배지는 운영(파랑) · 미운영(빨강) · 폐점(회색) 세 톤이다 — 폐점은 더는 손댈 일이 없는 상태라 미운영과 다른 색을 쓴다
* 사업자주소 입력은 항상 보이고, "점포 주소와 같음" 체크를 켜면 점포 주소 값을 읽기 전용으로 보여 준다(공통 `AddressField` 의 `labelExtra` · `disabled` prop)
* 층별 정보 입력 표는 일반 목록 표(DataTable)와 같은 모양이다 — 층구분부터 삭제까지 다섯 칸 너비를 모두 같게 둔다. [층 추가]는 표 위 왼쪽에 있다
* 위치 적용 여부는 좌표(위도·경도)가 있을 때만 사용으로 고를 수 있다. 새 점포 기본값은 미사용이다. 점포 주소를 지우면(지우기 버튼) 좌표와 함께 사용값도 미사용으로 돌아간다. 주소를 다시 고르거나 좌표를 손으로 고치는 것만으로는 이 값을 건드리지 않는다 — 지오코딩이 끝내 실패해 좌표가 비워진 채로 남을 때만 그 순간 미사용으로 맞춘다(재선택할 때마다 끄면 흔한 재선택 · 오타 수정에서도 운영 점포의 사용이 조용히 꺼지는 문제가 있었다). 선택칸에 보이는 값은 "좌표 있음 && 저장된 사용값"으로 계산해 항상 저장될 값과 같게 한다(그래서 좌표를 손으로 비웠다가 다시 채우면 사용이 저절로 되돌아와 보인다 — 저장 규칙과 일치하는 동작이다). 등록·수정 요청을 만들 때도 좌표가 없으면 사용값을 보내지 않고 미사용으로 막는다(front `bodyOf`) — 어느 경로로 좌표가 사라지든 저장 시점에 한 번 더 막는다. 수정 화면을 열 때도 좌표 없이 사용으로 저장된 옛 데이터를 미사용으로 바로잡는다. 상세 화면은 저장값과 상관없이 좌표가 없으면 미사용으로 보인다
* 상태 변경 팝업의 운영 조건은 폐점 조건과 같은 체크리스트 모양이다 — 사업자정보 인증 · 위치정보(위도 · 경도) 저장을 각각 완료 · 미인증 · 미저장으로 보인다(완료는 기본 글자색 볼드, 미인증·미저장은 빨강, 조건 이름 자체는 상태와 상관없이 기본색). 한글은 `GET /enums/StoreOperationRequirement` 라벨을 쓴다(front 에 대응표를 두지 않는다 — naming.md). 이 둘에 없는 운영 조건(예 BP_INACTIVE)도 체크리스트 아래 별도 줄로 보인다. 수정 화면의 점포상태 칸 아래 안내 문구도 같은 라벨 출처로, 모자란 조건을 한 문장에 모아 보인다
* 점포 등록 · 수정 화면의 [취소] [저장]은 화면 맨 아래가 아니라 제목 줄 오른쪽에 있다(근로계약서 작성 화면과 같은 자리) — 긴 폼에서 저장하려 끝까지 스크롤하지 않아도 된다
* 점포 상세의 대표 이미지 · 점포명 · 점포코드 · 점포유형을 제목 줄의 머리 카드 하나로 묶는다(디자인 데모로 탐색한 배치안 중 하나를 골랐다). 운영 상태 배지는 머리 카드에 두지 않는다 — 점포 기본정보 표 맨 줄(점포상태)과 정보가 겹쳐 보인다. 점포 기본정보 표에서는 대표 이미지가 빠지고 맨 윗줄은 점포코드 대신 점포상태다(코드는 머리 카드에만 남는다)
* 변경이력 줄의 등록 · 최종수정은 고정폭 대신 남는 폭을 반씩 나눠 가지며 넘치면 말줄임(…)한다 — 고정폭이던 전 버전은 처리자 이름이 길면(관리자 계정명 등) [변경이력] 버튼이 칸 밖으로 밀려 잘렸다
* 수정 화면에서 점포상태가 운영이면 점포 주소의 [지우기]를 숨긴다 — 운영 상태는 위도 · 경도가 있어야 하는데 그 좌표가 이 주소에서 나오니, 비워 둔 채로는 운영을 유지할 수 없다. 새 주소로 바꾸는 것(검색해 고르기)은 운영 중에도 그대로 된다
