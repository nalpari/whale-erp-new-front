같은 구조로 다룬다. 상태는 미운영 → 운영 → 폐점 한 방향으로만 가고, 한 번 폐점하면

# 정책

## 상태 · 권한

* 전환은 미운영→운영, 미운영·운영→폐점뿐이다. 운영을 미운영으로 되돌리지 않고, 폐점을 다시 열려면 새 점포로 등록한다 — `S-MNRZOM`
* 운영 전환 조건은 사업자정보 인증 · 필수 항목(점포유형·점포명) · 좌표(위도·경도) · 소속 BP 사용 상태 넷이다. 휴업·폐업 사업자인지는 보지 않는다 — `S-MNRZOM`
* 운영으로 바꾸거나 이미 운영인 점포는 사업자정보 인증 · 필수 항목 · 좌표가 있어야 한다. 연락처·주소 같은 선택 항목은 비어도 된다. 좌표가 없으면 운영으로 저장하지 않고, 상태 변경 팝업은 좌표가 남았음을 함께 알린다 — `S-MNRZOM` · `STORE-2`
* 폐점 조건은 진행 중인 근로계약 0건 · 이용 중인 구독 0건 · 정산 대기 0원이다. 구독·정산은 「1차 범위 밖」으로만 표시하고 1차에서는 진행 중인 근로계약만 확인한다(건수는 3팀 점포별 정보) — `S-MNRZOM`
* 폐점일은 바꾼 날로 자동이고 사유는 받지 않는다. 폐점 다음 날부터 그 점포에는 BP 휴일이 적용되지 않는다. 관리자 매핑은 그대로 두고 조회만 된다 — `S-MNRZOM`
* 점포 상태 변경은 점포 수정 권한이 있으면 역할을 가리지 않는다. 가맹 마스터·가맹 관리자도 매핑된 점포의 상태를 바꾼다 — `S-MNRZOM` · `STORE-1`
* 상태 변경은 상세의 상태 변경 팝업과 수정 화면의 점포상태 선택이 같은 조건으로 맡는다. 선택지는 현재 상태에서 갈 수 있는 곳만 보인다 — `S-MNRZOM` · `S-JEPOMK`
* 수정 화면에서 폐점을 고르는 순간 폐점 조건을 확인하고, 못 채우면 팝업으로 못 채운 조건을 보인 뒤 선택을 이전 상태로 돌린다. 조건을 채운 전환은 저장 때 확인 창을 거쳐 다른 수정 내용과 함께 반영하고, 저장 직전에 조건을 한 번 더 확인한다 — `S-JEPOMK`
* 소속 BP 가 미사용이면 목록·상세 조회만 되고 등록·수정·상태 변경·삭제는 막는다. 점포 상태는 그대로 둔다 — `F-MOQKGY`
* 목록·상세에 소속 BP 상태 칸은 두지 않는다. BP 미사용으로 막혔을 때만 안내를 보인다 — `S-BAYAJS` · `S-AGGZZG` · `STORE-3`
* BP 가 탈퇴하면 그 BP 의 미운영·운영 점포를 조건 검사 없이 모두 폐점한다 — `F-MOQKGY` · `S-JHQQNR`
* 가맹 마스터·가맹 관리자는 등록 권한이 켜져 있어도 점포를 등록할 수 없고, 매핑된 점포만 보고 고친다. 목록에서도 등록 버튼이 보이지 않는다 — `S-ALHLHW`
* 플랫폼 사용자는 전체 BP 의 점포를 보고, 화면 상단에서 고른 BP 로 점포를 등록한다. BP 를 고르기 전에는 등록 버튼이 비활성이다. 그 밖의 역할은 소속 BP 가 고정된다 — `S-BAYAJS` · `S-ALHLHW`
* 새 점포는 등록한 사람과 같은 BP 의 전체 점포 범위 사용자에게 자동으로 매핑된다. 플랫폼 사용자는 매핑 없이 전체를 본다 — `F-MOQKGY`
* 폐점 점포는 수정할 수 없다. 상세에 수정 버튼이 보이지 않고 주소로 직접 들어와도 저장하지 않는다 — `S-JEPOMK`

## 데이터 · 이력

* 점포유형은 등록 뒤 바꿀 수 없다. 점포코드는 입력 칸 없이 저장 뒤 시스템이 ST+6자리로 매긴다 — `S-ALHLHW`
* 점포명은 1~50자이고 같은 BP 안에서 겹쳐도 된다 — `S-ALHLHW`
* 사업자 인증 완료 여부는 따로 저장하지 않는다. 사업자등록번호가 있으면 인증된 것이고, 재인증에 실패해도 그대로다 — `F-MOQKGY`
* 사업자 번호 인증은 국세청 API로 사업자등록번호·대표자명·개업일자의 진위만 확인한다. 등록 단계에서는 선택이고 운영으로 바꿀 때 필요하다 — `S-ALHLHW`
* 한 번 저장된 사업자등록번호는 바꿀 수 없다. 재인증은 대표자명만 고치고, 번호가 바뀌면 기존 점포를 끝내고 새로 등록한다 — `S-JEPOMK`
* 상호명은 진위확인이 돌려주지 않아 인증과 상관없이 직접 입력하고, 재인증해도 바뀌지 않는다 — `S-ALHLHW` · `S-JEPOMK`
* 점포 사업자등록번호는 미운영·운영인 다른 점포와 겹칠 수 없다(플랫폼 전체). 폐점·삭제한 점포의 번호는 다시 쓸 수 있다. BP 사업자등록번호와는 따로 본다 — `PL-OCJOFP`
* 대표 이미지는 점포당 1장 · 선택 · JPG·PNG 5MB 이하다. 파일은 점포 대표 이미지 파일 테이블에 따로 두고 점포 테이블에는 경로를 두지 않는다. 바꾸거나 지우면 기존 파일 행을 삭제 처리한다 — `S-ALHLHW` · `S-JEPOMK`
* 목록 썸네일과 상세에 같은 대표 이미지가 보이고, 없으면 점포 아이콘이 선다. 엑셀에는 담지 않는다 — `S-ALHLHW` · `S-JEPOMK`
* 좌표는 주소로 자동 계산하고 직접 고칠 수 있다. 계산하지 못해도 미운영으로는 저장되지만, 운영으로 바꾸려면 좌표가 있어야 한다 — `S-ALHLHW`
* 근무지 반경은 점포에서 관리하지 않는다. 대신 위치 적용 여부(사용·미사용, 기본 사용)를 두고, 3팀이 사용인 점포에서만 위도·경도 기준으로 출퇴근 허용 여부를 판정한다 — `F-MOQKGY`
* 기타 정보는 층별로 둔다(점포 1 : 층 N). 층마다 층수·매장평수·전용면적·좌석수를 한 줄로 적고 모두 선택이다 — `S-ALHLHW`
* 근무직원 수는 그 점포를 근무지로 하는 재직 직원 수다 — `S-BAYAJS`
* 삭제는 미운영이면서 폐점 조건과 같은 세 조건을 채운 점포만 된다. 폐점 점포는 지우지 않고 보존한다 — `S-AGGZZG`
* 변경·삭제·상태 변경 이력은 5년 보존한다(탈퇴 BP 는 `PL-ZHHPAV` 우선). 변경 이력은 상세에서 조회 권한자에게 보이고, 삭제 이력은 운영 요청으로만 확인한다 — `F-MOQKGY`
* 수정을 저장하면 바뀐 항목마다 변경 전후 값·변경자·변경 일시가 변경 이력에 쌓인다. 변경 사유는 받지 않는다 — `S-JEPOMK`
* 화면을 연 뒤 다른 사람이 먼저 고쳤으면 저장하지 않고 최신 정보를 불러오게 한다 — `S-JEPOMK`

* 검색은 검색 기준(점포명 · 점포코드 · 사업자등록번호)을 고르고 검색어 하나를 넣으며, 점포상태 · 점포유형 체크와 AND 로 묶는다. 사업자등록번호는 하이픈을 빼고 비교한다 — `S-BAYAJS`
