whale-erp-front · API 연동 아키텍처

고객 로그인과 품목 목록이 whale-erp-api 를 호출하는 경로. JWT 는 서버에만 머문다.

요청 경로

브라우저는 whale-erp-api 를 직접 부르지 않는다. 인증도 조회도 Next.js 서버에서 일어나고, 액세스 토큰은 httpOnly 쿠키 안에만 존재한다. 브라우저의 JavaScript 는 토큰을 읽을 수 없고, API 를 부르는 주체는 언제나 서버다.

토큰의 일생

로그인 한 번으로 받은 액세스 토큰이 어디에 저장되고 언제 죽는지. 리프레시 토큰은 받자마자 버린다 — 자동 갱신을 하려면 쿠키를 다시 구워야 하고, 그것은 서버 컴포넌트가 할 수 없는 일이라 미들웨어나 라우트 핸들러가 필요해진다.

호출하는 엔드포인트

호출인증쓰임
POST /auth/customer/login 없음 (@Public) 고객 로그인. { accessToken, refreshToken, user } 반환
GET /items?take= Bearer 품목 목록. 기본 50, 최대 200
POST /auth/logout Bearer 서버에 저장된 리프레시 토큰 폐기

API 주소 주입. API_BASE_URL 은 모듈 로드 시점이 아니라 호출 시점에 읽는다. .env.development 는 http://localhost:8000, .env.production 은 비어 있고 배포 환경이 주입한다 — 빌드 시점에는 값이 없어도 되기 때문이다. 두 파일 모두 git 이 추적하지 않으므로 새 워크트리에는 따라오지 않는다.

실제 동작으로 확인한 경로다 — POST /auth/customer/login 200, 받은 토큰으로 GET /items?take=3 200. 인증 엔드포인트는 whale-erp-api 의 feat/wip 브랜치에 있다.
