# 초기 데이터 명세

서비스 오픈 전에 DB에 미리 들어 있어야 하는 데이터를 정리한다.
여기에는 **무엇을 넣을지**만 적는다. 실제로 넣는 시드 코드(`prisma/seed.ts` 등)는 `whale-erp-api` 저장소에 둔다.

값 전체는 [initial-data-request.md](initial-data-request.md) 에 있고, 시드 코드를 만드는 AI·개발자에게 그 파일을 그대로 넘긴다.
지금 담은 범위는 1팀 영역(인증·BP·점포·시스템 설정)이다.

ERD: [`docs/erd/team1/README.md`](../erd/team1/README.md)

## 규칙

- 테이블·컬럼 이름과 타입은 ERD(`docs/erd/`)를, 코드값·식별자 이름은 `okf/conventions/naming.md` 를 따른다.
- 공통코드의 상세 코드값과 코드명은 Manyfast 기능명세서(`F-KYIMYU 공통코드` 아래 13개 코드 명세)를 따른다. 2026-10-06 에 ⑩ 점포 유형 · ⑫ 약관 유형 · ⑬ 메일 유형을 명세 값으로 맞췄다.
- ERD가 바뀌면 이 명세도 함께 맞춘다. 맞추지 못한 것은 아래 「확인할 것」에 남긴다.
- 원자료(`docs/raw/`)와 달리 `/okf-ingest` 대상이 아니다. 계속 고쳐 가며 쓰는 명세다.

## 넣지 않는 것

- BP 관리자·가맹 관리자 권한 그룹 — 각 BP가 화면에서 만든다
- 직원 계정 · 알림 · 메일 양식 — 3팀 소유
- 임시공휴일·선거일 — 공공 API 동기화로만 받는다

## 확인할 것

- **기본키 이름:** 네이밍 규칙이 2026-10-02 에 `{참조 단수}_id` 로 바뀌었다. 요청서는 ERD를 따르라고만 적어 두어 영향은 없지만, ERD 물리 모델(`schema.sql`)과 한 번 맞춰 본다.
- **`ROLE_TYPE` 코드값:** `PM`·`PA`·`BM`·`BA`·`FM`·`FA` 로 확정. `role_groups.role_code` CHECK 제약(`^[A-Z]{2}[0-9]{6}$`)이 유형코드를 대문자 2글자로 요구한다. 용어집(`okf/conventions/naming.md`)도 2026-10-06 에 이 값으로 맞췄다.
- **Whale ERP 추가 메뉴:** 메뉴구조도에서 찾은 27건이다. URL 은 3팀 화면 경로와 맞춘다.
- **공휴일 규칙:** 실제 법령으로 한 번 확인한다.
