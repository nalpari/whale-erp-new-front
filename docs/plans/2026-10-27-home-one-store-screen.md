## 정한 것 (2026-10-27 재영)

- 업무 범위가 점포 하나(`scope STORE:n`)면 이 화면, 전체 · 직영 · 가맹이면 여러 점포 화면이다. 가맹마스터 · 가맹관리자(역할 유형 FM · FA)는 점포가 하나라 범위(전체 · 가맹)와 상관없이 그 점포로 이 화면이다.
- 처리 대기 · 점포별 현황 표 · 경고 밴드는 두지 않는다. 진입 · 범위 변경 때 부르고 그 밖에는 제목 줄 새로고침 버튼으로만 다시 부른다.
- api 는 새로 만들지 않는다. 데이터가 없는 칸(점장 · 영업시간)은 빼고 1팀에 요청하지 않는다. 직원 급여 카드는 api #621(api #174)이 머지된 뒤 후속 PR 로 붙였다(2026-10-28).
- 직원 정보의 근무 시간 · 근무요일: api 는 #622(api #171)로 준비됐고, 관리자 웹 열은 1팀 /bp-masters api 가 api main 에 들어와 타입을 다시 만들 수 있을 때 후속 PR 로 붙인다(2026-10-27 재영). 붙일 때 근로계약 관리 조회 권한이 없으면 두 칸을 비운다.
- 근무스케줄(읽기 전용)에서 가린 직원도 관리 화면처럼 이름 · 막대 없는 줄로 보인다 — 근무 인원 줄과 줄 수를 맞춘다(2026-10-27 재영).
- 직원 정보 표의 가린 줄은 짧은 「본사 제공 동의 없음」이고, 「재직 N · 가입 대기 M」에 넣지 않고 「가려진 직원 K」로 따로 센다(K 가 0 이면 안 보임, 2026-10-27 재영).
- 권한이 없는 카드 · 버튼은 숨긴다(메뉴 조회 · 등록 권한). 카드 하나가 실패하면 그 카드만 오류와 [다시 시도].
- 본사 역할(BM · BA)의 본사 제공 동의 가림은 각 api 가 한다. 화면은 `isMasked` 를 따르기만 한다.

## 화면 · api

| 영역 | api | 보이는 것 | 권한(메뉴 조회) |
|---|---|---|---|
| 공지 띠 | `GET /support-notices?pageSize=20` | 게시일 최신 3건(고정 여부와 상관없이, `latestNotices`) · [공지 목록] | 공지사항 `/support-notices` |
| 운영 점포 정보 | `GET /stores/:id` | 점포명 · 유형 · 전화번호 · 개점일(`business.openDate`) · [점포 정보 관리] | 점포 정보 관리 `/stores` |
| 직원 급여 | `GET /payslips/summary?storeId=n&month=이번 달` | 「M월 급여 지급 예정」 합계 · 직원 N명 · 정직원 · 파트타이머별 인원과 금액(만원 반올림, 만원 미만은 원 — `manWon`) · [급여명세서](이번 달 · 그 점포 목록) | 급여명세서 관리 `/payslips` |
| TO-DO | `GET /todos?storeIds=n` 두 번 — 오늘 전부(`pageSize=200`) · 긴급(`total`) | 오늘 완료 / 오늘 전체 · 진행 막대 · 대기·진행 중 N건 · 긴급 N · 오늘 것 앞 2건 · [TO-DO 리스트] | TO-DO `/todos` |
| 내 문의 | `GET /support-inquiries` 두 번 | 답변 대기(접수 · 처리중) N건 · 전체 N건 · 최근 2건 · [문의 내역] | 문의하기 `/support-inquiries` |
| 근무스케줄 | `GET /work-schedules?storeId&from&to` | 주간 · 월간 보기(아래) · [근무스케줄 관리] | 근무스케줄 `/work-schedules` |
| 직원 정보 | `GET /staff-members?storeIds=n&employmentStatus=EMPLOYED&pageSize=100` | 직원 · 구분 · 근로계약 · 상태 · [근로계약 관리] [직원 관리] [계약서 작성] | 직원 정보 관리 `/staff-members` |

- **TO-DO 세는 법:** 오늘 전체 = 수행 예정일이 오늘인 줄 수(`dueDateFrom=dueDateTo=오늘`의 total), 오늘 완료 = 받은 줄 가운데 `status` 가 완료인 것 — 근무지 전체 배정은 묶음 상태라 모두 완료해야 완료다. api 의 `status=DONE` 필터는 행에 걸려 한 명만 끝낸 묶음도 완료 줄로 와서 쓰지 않는다(front #153 리뷰). 대기·진행 중 = 오늘 전체 − 오늘 완료, 긴급 = 날짜와 상관없이 대기 · 진행 중인 긴급. 근무지 전체 배정은 한 줄을 한 건으로 센다(목록과 같다). 한계: 오늘 것이 200줄을 넘으면 완료는 앞 200줄 기준이고 「(앞 N건 기준)」을 붙인다. 「미완료」는 TO-DO 상태 이름이 아니라 쓰지 않는다.
- **직원 정보 상태 칸:** 임시저장만 있는 레코드(DRAFT)는 재직이 아니라(운영 정책 CTR-29) 표와 수에서 빼고, 연결 보류(LINK_HOLD)는 없앤 규칙이라 함께 뺀다. api 의 `joinState` 조건으로 빼지 않고 받은 줄 가운데 보이는 줄만 화면에서 거른다(`staffRowsOf`) — 직원 목록 api 는 본사 역할이 가입 상태 같은 개인 칸으로 거르면 가려지는 가맹 점포 직원 줄을 통째로 빼서(api `staff-member-list.service.ts` filtersPersonal, 재직 상태는 예외) 「가려진 직원 K」가 늘 0 이 된다(#153 재확인). 가린 줄은 `joinState` 가 null 이라 남는다. 「가입 대기」는 초대 발송 · 초대 만료 · 거절 · 소속 추가 확인 · 복귀 확인(HOME-9), 만 19세 미만은 「가입 불가(만 19세 미만)」, 가입한 직원은 「재직」과 퇴직일이 정해졌으면 「퇴직 예정 MM-DD」. 근로계약 칸은 직원 목록과 같은 표시(`contractCell`). 가린 행은 「본사 제공 동의 없음」(TO-DO · 급여명세서와 같은 짧은 문구)이고 나머지 칸은 「—」. 제목 옆에 「재직 N · 가입 대기 M」, 있으면 「· 가입 불가 U」 · 「· 가려진 직원 K」. 수는 그렇게 거른 줄(100명까지 받은 것)로 센다 — 가린 직원은 api total 로 가를 수 없어서다. 거르기 전 받은 줄이 total 보다 적으면(100명 초과) 「(앞 100명 기준)」을 붙이고 표 아래 「전체는 직원 관리에서」. [계약서 작성]은 근로계약 관리 등록 권한일 때만. 직원이 없으면 빈 상태와 [계약서 작성].
- **근무스케줄:** 근무스케줄 관리의 `ScheduleWeek` · `ScheduleMonth` 를 그대로 쓰고 두 prop 을 더한다 — `hrefBase`(링크 기본 경로, 기본 `/work-schedules`)와 `readOnly`(기본 false). 관리 화면은 두 prop 을 주지 않아 지금과 같다.
  - `readOnly` 면 그날 근무가 있는 직원과 근무 인원에서 그 수를 뺀 만큼의 가린 직원 줄(`readOnlyRows` — 휴무 직원 행 없음), 막대는 누를 수 없는 글자(시간만, 자정을 넘으면 「익일」), 공백 줄 · 배정 버튼 없음. 근무 인원 줄 · 범례는 그대로.
  - 보기 상태(주간 · 월간 · 주 · 날 · 달)는 홈 주소의 쿼리에 둔다(`/home?view=month&day=…` — 근무스케줄 관리와 같은 파서 `parseScheduleQuery` · `toScheduleSearch`, 점포는 싣지 않는다). 주간은 이전 · 다음 주와 주 표시, 월간은 왼쪽 고른 날 근무자 · 이전 · 다음 날, 오른쪽 달력 · 이전 · 다음 달 · 이번 달.
- **공지 띠:** api 는 고정 공지를 먼저 주고(정렬 파라미터 없음) 그 뒤를 게시일 최신순으로 준다. 20건을 받아 게시일로 다시 골라 최신 3건을 보인다 — 고정 공지가 18건 이상이면 맞지 않을 수 있다.
- 제목 줄의 「MM-DD HH:mm 기준」은 이 화면에 없다 — 영역마다 따로 불러 한 시각이 없다.

## 목업 · 데모 정리

- 운영 점포 정보에서 점장 · 영업시간 줄을 빼고 전화번호를 넣는다.
- 직원 정보 표의 「연결 보류 · 번호 불일치 / 가입 대기」 줄을 「초대 발송 → 가입 대기」 예로 바꾼다.
- 쟁점 HOME-9(확정 · 2026-10-27 재영)를 더한다: 점장 · 영업시간은 1팀 점포 데이터에 없어 뺀다(1팀에 칸 요청 안 함) · 직원 정보 상태 칸은 재직 · 퇴직 예정 + 미가입은 가입 대기 · 직원 급여 합계는 귀속월 이번 달 모든 상태, 본사 역할은 미동의 가맹 직원 제외(#621) · 근무 시간 · 근무요일은 #622 · api 는 기존 목록을 쓰고 없는 것만 요청.

- 직원 정보 표의 근무 시간 · 근무요일 열 — api #622(api #171) 준비됨. 1팀 /bp-masters api 가 api main 에 들어와 타입을 다시 만들 수 있을 때.

- **직원 급여:** 귀속월은 이번 달(급여 기간 시작일이 그 달 — 급여명세서 목록의 달과 같다), 작성 중 · 검토 중 · 확정 · 발송 완료 모두 더한다. 본사 역할의 본사 제공 동의 거르기는 api 가 해서 화면은 거르지 않는다(ATT-30). 본사 역할(BM · BA)이 가맹 점포를 보면 카드 아래에 「동의하지 않은 가맹 직원은 급여 합계에 세지 않습니다」를 늘 붙인다 — 여러 점포 화면 수치 카드의 안내와 같다(HOME-10 B안, 2026-10-28 재영). 관리자 웹 api 타입은 1팀 /bp-masters 가 들어온 api main openapi 로 다시 만들었다(2026-10-28).
