# 플랫폼 계정이 고른 BP 의 로그인 후 홈 — front (WHALEERP-667)

근거: 2026-11-12 재영 결정, 운영 정책 v280 HOM-07. api PR(grimer)이 먼저 머지되어야 한다.

## 정한 것

- 플랫폼 마스터 · 플랫폼 관리자가 범위 선택기에서 고객 BP 를 골라 웨일ERP 탭(service `WHALE_ERP`)에 오면 BP 마스터와 같은 홈을 본다. 공지 띠 · 수치 카드(내 문의 포함) · 점포별 현황 · 확인 필요(문의 답변완료 포함) 모두다. 공지 띠는 공지사항 조회 권한이 있으면 보인다. 플랫폼 계정에게는 그 BP 의 BP 마스터와 같은 공지(회원 + BP 대상)가 보이고, 띠에서 누른 공지는 공지사항 상세 · 목록에서도 보인다(2026-11-12 재영, HOM-07 v281 — api 가 탭 BP 로 노출 대상을 고른다).
- BP 를 고르지 않은 플랫폼 계정 홈(플랫폼 탭)은 지금 안내(Platform 콘솔 버튼) 그대로다.
- 인사 옆 「OOO · BP코드 의 홈화면을 보고 있습니다」 꼬리표는 그대로다.

## 바꾸는 것

- `src/app/home/home-screen.tsx`
  - 안내 화면으로 가르는 조건을 「플랫폼 계정」에서 「플랫폼 계정이고 웨일ERP 탭이 아님」으로 바꾼다. `noStores` · `many` 판정도 같은 조건을 쓴다. 고른 BP 에 점포가 없으면 BP 마스터처럼 값 0 화면이다.
  - 홈은 `/bp/{id}` 주소로 옮긴 화면이 아니라 bff 가 주소에서 탭 BP 를 읽지 못한다. `/home/summary` · `/home/pending` 과 공지 띠의 `/support-notices` 를 부를 때 탭 BP 를 직접 싣는다.
- `src/lib/bff.ts` · `src/lib/use-load.ts`: 주소에 BP 가 없을 때 쓸 탭 BP 를 받을 수 있게 인자 하나를 더한다(주소의 BP 가 먼저다).
- `api-types.generated.ts` 를 api grimer 기준으로 다시 만든다.

- `node --test` 전체, tsc · eslint · `next build --webpack`.
