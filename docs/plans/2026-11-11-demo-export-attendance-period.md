# 데모의 직원 자료 일괄 저장 · 출퇴근 현황을 앱에 맞춘다

근거: 2026-11-11 재영 결정(기획 세션 header 전달). 납품 화면설계서는 데모를 찍어 만든다. #251(일괄 저장 문구)과 #252(급여명세서에서 연 기간 기록, WHALEERP-664)는 앱만 고쳐서, 데모를 앱에 맞춘 뒤 그 화면만 다시 찍는다.

## 고칠 것

- `docs/demo/src/pages/staff/export.mjs`: #251의 앱 문구로 바꾼다. 묶음 이름(저장되는 자료 · 요청 내역 · 새 요청), 표 머리(구분 · 포함 내용 · 파일 형식 · 대상 직원 · 파일), 상태(파일 생성 중 · 다운로드 가능 · 기간 만료), 대상 점포 · 대상 직원 · 파일 형식 칸, 탈퇴 안내와 보관 책임 안내가 대상이다.
- `docs/demo/src/staff-sections.mjs`: 보정 목록 묶음을 함수로 묶고, 급여명세서에서 온 모습(`attendPeriodTab`)을 더한다. 제목은 「기간 출·퇴근 기록」, 기간은 첫 주 월요일부터(2026-07-27 ~ 08-31)다. 줄은 그 직원의 기간 기록이고, 표 아래 안내 한 줄을 붙인다.
- 새 화면 `docs/demo/src/pages/staff/attendance-period.mjs` → `staff/attendance-period.html`.
- `docs/demo/src/pages/staff/payrolls-detail.mjs`: [출퇴근 기록 확인] · [출퇴근 기록 보기]를 새 화면으로 잇는다.

## 하지 않는 것

- 앱 코드.
- 데모 배치. 앱에 없는 「만드는 중」 · 「받은 뒤」 묶음은 그대로 둔다.
- 기간 기록 화면에 결근 줄은 넣지 않는다. 급여명세서 데모의 경고(8월 28일 퇴근 미등록 · 8월 22일 출근·퇴근 미등록)와 맞추기 위해서다.
- 다른 화면 산출물. 다시 빌드하면 모든 HTML의 캐시 버전 값 `?v=`가 바뀌지만, 고친 화면 넷만 담는다.

## 검증

- `node docs/demo/build.mjs`.
- 두 화면을 1440 폭으로 찍어 문구 · 줄 · 안내를 눈으로 본다. `staff/attendance.html`은 요소 ID 번호와 `?v=`만 바뀌었다.
