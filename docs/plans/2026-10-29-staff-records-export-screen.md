# 직원 자료 일괄 저장 화면 (WHALEERP-337)

근거: 운영 정책 RET-09 · NTF-01, Manyfast 「직원 자료 일괄 저장」 명세, Plane 337 완료 조건, 목업 `docs/mockup/staff/export.html`.
API 는 whale-erp-api `docs/plans/2026-10-29-staff-records-export.md`(Plane 336)를 쓴다.

## 진입점

- 직원 목록 툴바에 이미 있는 [일괄 저장](`/staff-members/export`)을 BP 마스터(`BM`)와 가맹마스터(`FM`)에게만 보인다. 지금은 모든 역할에게 보인다.
- 다른 역할이 주소로 들어오면 「일괄 저장은 BP 마스터와 가맹마스터만 쓸 수 있습니다」를 보인다. API 도 403 으로 막는다.
- 1팀 회원 탈퇴 화면의 바로가기도 같은 주소(`/staff-members/export`)로 들어온다. 탈퇴 화면을 고치는 일(339)은 1팀과 협의할 일이라 여기서 하지 않는다.

## 화면 (`/staff-members/export`)

목업의 순서를 따른다. 공통 컴포넌트와 DESIGN.md 토큰을 쓴다.

1. 탈퇴 안내 상자(`PendingNotice`): BP 가 탈퇴하면 관리자 계정이 모두 미사용이 되어 자료를 볼 수 없다. 필요한 자료는 탈퇴 전에 받아 둔다.
2. 담기는 자료 네 가지 표. 자료(근로계약서 · 출퇴근 기록 · 급여명세서 · 근무스케줄), 담기는 것, 형식(PDF · CSV)을 적는다. 그 아래에 「주민등록번호 · 신고 정보 · 확인자료 · 동의 기록은 담지 않습니다」를 둔다.
3. 새로 요청: 업무 범위(범위 선택기 값), 대상 직원 수(재직 N · 보존 기간 안 퇴직 N), 파일 형식(ZIP 한 개, 직원별 폴더), [일괄 저장 요청] 버튼.
   - 대상이 0명이면 버튼을 끄고 「업무 범위에 담을 직원 자료가 없습니다」를 보인다.
   - 같은 범위가 만드는 중이면 버튼을 끄고 그 사실을 적는다.
4. 지난 요청 표: 요청 일시, 요청자, 대상 직원 수, 상태.
   - 상태는 「만드는 중」(대기 · 만드는 중), 「받을 수 있음 · MM-DD 까지」와 [내려받기], 「기한 지남」, 「실패」와 [다시 요청]이다.
   - BP 마스터 파일은 내려받기 직전에 api 가 담긴 직원의 본사 제공 동의 · 점포 상태를 다시 본다. 바뀌었으면 409 와 「파일을 만든 뒤 담긴 직원의 동의나 점포 상태가 바뀌었습니다. 다시 요청해 주세요」가 온다. 화면은 그 문구를 그대로 보이고 새로 요청하게 한다(2026-10-29 재영, 운영 정책 RET-09).
   - 운영 알림은 보내지 않는다(NTF-01). 만드는 중인 요청이 있으면 10초마다 목록을 새로 읽는다.
5. 보관 책임 안내: 내려받은 파일의 보관 책임은 BP 에 있다. 이름 · 휴대전화번호 · 급여가 담긴 파일이다.

받을 수 있는 기한은 7일이고, 이 값은 api 가 주는 `expiresAt` 으로 보인다.

## 범위

- 헤더 범위(`?scope=`)를 `scopeStores` 로 점포 id 로 바꿔 `storeIds` 로 넘긴다. 「전체」면 빈 값이다.
- 범위를 바꾸면 대상 직원 수를 다시 읽는다. 범위 선택기는 보통 그 메뉴의 목록(`/staff-members`)으로 가지만(2026-10-21 정책), 이 화면은 지금 범위로 일하는 화면이라 머문다. 헤더가 같은 주소에 새 `?scope=` 만 실어 바꾼다(2026-10-29 front #179 리뷰).

## 확인

- `pnpm lint` · `pnpm exec tsc --noEmit` · `pnpm build`
- 순수 함수(상태 표시 · 범위 → storeIds)는 `node --test` 로 확인한다.
- 로컬 api 에 붙여 BM · FM 으로 요청 → 만드는 중 → 내려받기, BA 진입점 숨김, 기한 지남 표시를 눈으로 확인한다.
