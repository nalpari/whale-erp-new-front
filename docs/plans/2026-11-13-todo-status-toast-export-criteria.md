# TO-DO 상태 변경 토스트 · 일괄 저장 대상 기준 안내

근거: 2026-11-13 재영이 Plane 인테이크에서 수락했다(기획 세션 header 전달). WHALEERP-693, WHALEERP-678.

## 고칠 것

- WHALEERP-693: `src/app/todos/[id]/todo-detail-actions.tsx`의 [상태 변경] 성공 토스트를 「수정되었습니다.」(`toast("updated")`)에서 「변경되었습니다.」로 바꾼다.
  - 공통 토스트 키는 저장 · 수정 · 삭제 셋뿐이고, 그 밖의 문구는 문자열로 넘기는 것이 `toast.tsx`의 규칙이다. BP 상세의 상태 변경도 `toast("변경되었습니다.")`로 쓴다. 그래서 키를 늘리지 않고 같은 방식을 따른다.
  - TO-DO 상세의 다른 [수정] 저장 토스트는 그대로 둔다.
- WHALEERP-678: `src/app/staff-members/export/export-screen.tsx`의 새 요청 카드에 세는 기준을 적는다.
  - 대상 점포: 전체 범위(화면이 빈 점포 목록을 보내 api가 관리 점포 전부를 셀 때)에서만 점포 수 옆에 「폐점 점포 포함」을 붙인다. 직영 · 가맹 · 점포 하나 범위는 화면이 폐점을 빼고 보내므로 붙이지 않는다(리뷰 반영).
  - 대상 직원: 표 바로 아래 안내 한 줄을 둔다. 대상은 재직 직원(근로계약서가 작성 중이 아닌 직원)과 퇴직 3년 이내 직원이다. 작성 중 계약만 있는 직원은 빠지므로, 상단 범위의 점포 수나 직원 목록 건수와 다를 수 있다고 알린다.
  - BP 마스터에게만 「본사 제공 동의를 하지 않았거나 폐점한 가맹 점포의 직원도 빠집니다.」를 덧붙인다(2026-11-13 재영). 가맹마스터에게는 넣지 않는다. 역할 판정 `isHqRole`(BM · BA)은 api가 BP 마스터 파일을 거르는 기준(`admin-scope.service.ts` HQ_ROLES, `bulk-export-policy.ts`)과 같다.
  - 숫자 기준(api `bulk-exports.service.ts`)은 바꾸지 않는다.
