- 작성: 3팀 기획 세션 · 2026-10-02

## 목적

목업(`docs/mockup/`)의 화면을 DESIGN.md(1팀이 Figma 에서 옮긴 디자인 시스템)의 생김새로 옮긴 **정적 HTML 데모**를 만든다.
앱 코드(`src/`)를 만드는 일이 아니다.

## 범위

- 관리자 웹 목업 57개 화면 — 1팀(auth 6 · bp 4 · stores 6 · config 10 · system 8 · mypage 3), 3팀(home 5 · staff 7 · support 7 · notify 1).
- 직원 근무 앱 목업은 뺀다. DESIGN.md 가 관리자 웹용이다.
- 목업 원본은 고치지 않는다. 데모는 `docs/demo/` 에 따로 둔다.

## 옮기는 기준

- 구조와 내용은 목업에서, 생김새는 DESIGN.md 에서 가져온다.
- 뺀다: 쟁점 블록, `band__desc`, `panel__note`, `gap__note`, `gap__ref`, 명세 ID(S-…), 화면 정의서·목업 허브 링크, 상태 시연 버튼(`demo`).
- 남긴다: 사용자에게 보이는 안내 문구(`note`), 탭, 토글.
- 상태 시연 버튼으로만 보이던 상태는 넣지 않고 기본 상태만 둔다.

## 만드는 방식

- 마크업은 1팀 공통 컴포넌트(`src/components/common/`)가 그리는 HTML 과 같은 클래스를 쓴다. `/design` 화면을 렌더링해 얻은 마크업이 기준이다.
- 화면은 `docs/demo/src/pages/**/*.mjs` 하나가 한 장이고, `src/ui.mjs`(1팀 공통 컴포넌트를 HTML 로 옮긴 함수)로만 그린다. 헤더·메뉴·로그인한 사람은 `src/site.mjs` 한 곳에 둔다.
- `node docs/demo/build.mjs` 가 화면 HTML 과 `assets/erp.css` 를 함께 만든다. 토큰은 `src/app/globals.css` 의 ERP `@theme` 블록을 그대로 읽어 온다(두 곳에 적지 않는다).
- 아직 만들지 않은 화면으로 가는 링크는 `#` 로 둔다(`site.mjs` 의 `link`).
- 공통 컴포넌트에 없는 부품(토스트, 확인창 등)은 데모에서 지어내지 않고 따로 제안한다.

## 주의

- 앱의 Tailwind 는 `docs/` 까지 훑는다. 데모 HTML 에 앱에 없는 클래스를 쓰면 그 클래스가 앱 CSS 에도 들어가고, 파일 경로를 담은 클래스(배경 이미지 등)는 앱 빌드를 깨뜨린다(2026-10-02 실제로 깨졌다). 데모에서는 경로를 담은 클래스를 새로 만들지 않고, 필요하면 `assets/base.css` 에서 덮는다. 근본 해결은 앱 `globals.css` 에 `@source not` 으로 `docs/` 를 빼는 것인데 1팀 파일이라 따로 제안한다.
- 브라우저에서 꺼낸 HTML 은 class 안의 `&` `>` 가 `&amp;` `&gt;` 로 바뀌어 있다. 원래 글자로 되돌려 둬야 Tailwind 가 `[&_*]:…` 같은 클래스를 읽는다. 그대로 두면 스크롤바 굵기 같은 스타일이 빠진다.
