공통 — 여러 화면이 함께 쓰는 다섯 가지

VISUAL IDENTITY

이 폴더가 원래 쓰던 archify 뷰어(라우트 추적 · 시맨틱 레이더 · 가이드 스토리 등 인터랙티브 기능 포함)는 이 환경에 설치돼 있지 않아, 실제 화면의 툴바 · 가이드 뷰 · 레인 · 범례 구성을 그대로 옮기되 정적 SVG로 손으로 그렸다. 같은 폴더의 common.workflow.json이 archify가 실제로 읽는 원본 모델이라, archify를 쓸 수 있는 곳에서 그 파일을 그대로 넣으면 라우트 추적 등 인터랙션까지 포함해 다시 만들 수 있다. (Theme 버튼만 실제로 동작한다.)

이 장은 하나로 이어지는 여정이 아니라, 다른 업무 화면들이 공통으로 가져다 쓰는 다섯 개의 독립된 도구를 한 장에 모은 것이다 — 그래서 왼쪽부터 공통 컴포넌트 · 공통코드 · 메일 포맷 · 약관 콘텐츠 · 상단 조회 범위 선택 다섯 구획으로 나뉘어 있고, 구획 사이에는 억지 연결선을 넣지 않았다.

짚어둘 세 가지.
  1. 공통코드의 관리 주체가 플랫폼고정 · 플랫폼제공 · BP전용 세 갈래로 BP가 어디까지 고칠 수 있는지를 가른다.
  2. GNB 점포 드롭다운은 현재 BP 안에서만 범위를 바꾸는 인라인 드롭다운이고, BP 자체를 바꾸려면 반드시 BP 변경 버튼으로 별도 팝업을 열어야 한다 — 고객 사용자(BP 측 관리자)에게는 이 버튼 자체가 없다. 점포를 고르는 방식은 둘이 같고(검색·그룹 전체·개별 단일·복수), 차이는 폐점 점포 표시 여부뿐이다(팝업엔 보이고 선택 불가, 드롭다운엔 안 보임). 적용한 범위는 목록 화면 진입 시 그 화면 왼쪽 필터의 기본값일 뿐이라 화면 안에서 GNB 범위 밖 점포로 자유롭게 바꿀 수 있다 (2026-09-30 확정, F-TLJOCK).
  3. 약관 콘텐츠는 열람 전용 참조 콘텐츠다 — 동의 체크박스와 필수 검증 UI는 이 기능이 아니라 BP 회원가입 같은 소비 기능이 담당한다. 플랫폼 이용약관은 받는 대상이 갈려 BP사업자 회원가입용 · 직원앱 회원가입용 두 본문으로 나뉜다.
  4. 화면 하나가 아니라 여러 화면에 걸리는 UI 공통 규칙(URL 직접 접근, 삭제 확인, 저장·오류 토스트, 로그인 후 이동 등)은 이 장이 아니라 목업 LNB의 공통(협의필요) 꼭지 — docs/mockup/policy/overview.html — 에 따로 모아 둔다.

확정된 결정

사업자 인증 팝업은 상호명을 조회·반환하지 않는다(사용자가 직접 입력) · 임시·초기 비밀번호 원문은 발송 외에는 저장·재표시하지 않는다 · 공통코드 값의 추가·변경·중지는 공통코드 관리에서만 일관 적용한다. 가입경로(회원가입·플랫폼등록)는 계정 생성 시 한 번 정해지면 이후 바꿀 수 없다. 사용 중지된 공통코드 값은 기존 이력엔 남지만 신규 선택 대상에서는 영구히 빠진다.

밖에 있는 것

약관 동의 체크박스 · 필수 검증 UI는 이 기능이 아니라 BP 회원가입 같은 소비 기능이 담당한다. 사업자정보 인증 · 주소 검색 · 점포 검색은 결과만 호출 화면에 돌려주고 저장 권한은 갖지 않는다. BP 변경 버튼은 고객 사용자(BP 측 관리자)에게는 아예 없다 — 플랫폼 마스터 · 관리자 전용이다.
