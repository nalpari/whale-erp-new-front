VISUAL IDENTITY

이 폴더가 원래 쓰던 archify 뷰어는 이 환경에 설치돼 있지 않아, 실제 화면의 툴바 · 가이드 뷰 · 레인 · 범례 구성을 그대로 옮기되 정적 SVG로 손으로 그렸다. 같은 폴더의 platform-admin.workflow.json이 archify가 실제로 읽는 원본 모델이라, archify를 쓸 수 있는 곳에서 그 파일을 그대로 넣으면 라우트 추적 등 인터랙션까지 포함해 다시 만들 수 있다. (Theme 버튼만 실제로 동작한다.) 여섯 기능(BP 마스터 계정 관리 · 플랫폼 관리자 관리 · 권한 관리 · 메뉴 관리 · 휴일 관리 · 공통코드 관리)을 플랫폼 운영자 화면이라는 공통 축으로 한 장에 묶었다.

핵심 갈림길 셋. ① 서비스 공통코드 → 메뉴 → 권한은 이 순서로만 등록할 수 있다 — 메뉴가 없으면 권한 화면에서 메뉴별 CRUD를 설정할 수 없다. ② 사용 상태 플랫폼 마스터는 항상 1명 이상 있어야 해서, 마지막 1명은 미사용 전환 · 권한변경 · 삭제를 모두 거부당한다. ③ BP 마스터 계정 탈퇴는 소속 점포를 폐점 조건 검증 없이 전부 폐점 처리한다.

확정된 결정

서비스 공통코드 → 메뉴 → 권한은 이 순서로만 등록 가능 · 플랫폼 관리자 계정 상태는 사용 · 미사용 두 값만(탈퇴 없음) · 휴일 정보는 조회 전용이며 동기화 배치만 채운다. BP 탈퇴 처리 시 소속 점포는 폐점 조건 검증 없이 전부 폐점으로 전환되며 되돌릴 수 없다. 삭제한 BP 마스터 계정의 아이디는 재사용이 막히지만 기록은 남는다. 플랫폼 메뉴는 삭제 기능이 없고 사용중지만 가능하다.

밖에 있는 것

개별 점포의 운영 데이터(직원 · 근로계약 · 정산)는 다루지 않는다 — 점포정보 관리 화면이 맡는다. BP 소속 하위 관리자(BP 관리자 · 가맹 마스터 등) 계정 관리도 여기 없다 — BP 환경설정 화면이 맡는다. 본인 계정의 상태 · 권한 변경은 이 화면에서 스스로 할 수 없다.
