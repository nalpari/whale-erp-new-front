# Plane WhaleERP 구성 기준

미니(`http://172.30.1.65:3333`)의 Plane 워크스페이스 `whale-erp`, 프로젝트 **WhaleERP**를
어떻게 짜 두었는지 적는다. 비우고 다시 만들 때 같은 모양이 나오게 하는 것이 목적이다.

기준일 2026-09-21 · 정한 사람 재영 · 옮긴 세션 기획

---

## 1. 무엇을 Plane에 넣는가

Plane은 **할 일을 두는 곳**이다. 요구사항과 명세의 원본은 Manyfast, 화면은 목업, 운영 규칙은
운영 정책 아티팩트에 있다. Plane에는 그것들을 가리키는 작업만 둔다.

| 층 | 무엇 | 어디서 왔나 |
|---|---|---|
| 맨 위 | Manyfast **명세** 26건 | Manyfast의 명세 이름 그대로 |
| 그 아래 | **결정 대기** 항목 | 목업 쟁점 |
| 그 아래 | **개발 작업** | 명세를 쪼갠 것 |
| 따로 | **외부 검토**, **선행 조건**, **공통 기반** | 화면에 매이지 않는 것 |

**기능 부모는 두지 않는다.** 처음에는 Manyfast의 기능을 작업으로 만들어 명세를 그 밑에 달았는데,
층이 하나 늘 뿐 쓸모가 없어 지웠다 (2026-09-17). 명세가 최상위다.

**사이클은 쓰지 않는다.** 착수 순서는 명세 본문과 선행 관계(`blocked_by`)로 나타낸다.

## 4. 작업 규칙

- **이름**: 결정과 검토는 `[쟁점 ID] 질문` 꼴로 쓴다. 예 `[PAY-1] 확정 취소로 명세서가 바뀌면 어떻게 알릴까`
- **본문**: 후보 안과 근거, 목업 쟁점 번호, 참고 화면 주소를 적는다
- **부모**: 결정과 개발 작업은 그 **명세 작업**을 부모로 둔다
- **선행**: 착수 순서는 `blocked_by` 관계로 건다 (처음 넣을 때 51건 + 개발 작업 14건)
- **중복 방지**: 모든 작업에 `external_source = whale-plan`과 `external_id`를 넣는다. 다시 돌려도
  같은 `external_id`면 새로 만들지 않는다
- **상태**: Backlog · Todo · In Progress · Done · Cancelled 다섯을 그대로 쓴다.
  2차로 미룬 것은 Done이 아니라 **Cancelled**로 두고 이유를 댓글로 남긴다

## 5. 다시 만들 때

스크립트는 스크래치패드의 `plane-seed/`에 있다. 저장소에 두지 않은 것은 API 토큰을 읽기 때문이다.

| 파일 | 하는 일 |
|---|---|
| `seed.py` | 맨 처음 76건을 넣은 스크립트. **옛 구조 기준이라 그대로 다시 돌리면 안 된다** |
| `restructure.py` | 요구사항 모듈을 지우고 기능 모듈 15개를 만든 뒤 기능 부모를 지운다 |
| `create_tasks.py` | 모듈 하나의 개발 작업을 명세 밑에 만든다 |
| `ids.json` | 명세·결정 항목과 Plane 작업 id의 짝 |

주의할 것 넷.

1. **호출 간격 1.1초.** 분당 제한이 있어 더 빠르게 돌리면 429가 난다
2. **부모를 지우기 전에 자식이 풀렸는지 확인한다.** 그러지 않으면 자식까지 함께 지워진다
3. **커뮤니티 판에는 작업 유형과 Epic API가 없다.** 계층은 부모-자식으로만 만든다
4. **웹훅이 돌아 BUZZ에 알림이 간다.** 한꺼번에 많이 바꿀 때는 미니의 중계기를 잠시 멈춘다
