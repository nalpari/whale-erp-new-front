BP 가 자기 관리자·권한·코드·휴일을 스스로 정하는 곳이다

무엇을 볼 수 있는지는 메뉴별 CRUD 권한과 점포 매핑을 둘 다 통과한 범위다. BP 마스터·BP 관리자·가맹 마스터·가맹 관리자가 같은 화면을 보지만 역할마다 대상과 할 수 있는 일이 다르다. 각 화면 위의 점선 줄로 보는 사람을 바꿔 가며 무엇이 보이고 막히는지 볼 수 있다. BP 마스터 계정과 BP 자체는 여기가 아니라 플랫폼의 BP 마스터 계정 관리 몫이다.

계정 · 권한 그룹

7
  • 대상은 BP 관리자·가맹 마스터·가맹 관리자 계정이다. BP 마스터와 BP 자체, 플랫폼 관리자 계정은 여기 없다.F-OILWTZ · PL-RWJYLJ
  • 가맹 관리자 계정의 등록·수정·비밀번호 초기화는 가맹 마스터만 한다. 다른 역할은 메뉴 권한이 있어도 조회만.F-OILWTZ
  • 가맹 관리자는 가맹 마스터를 먼저 연결하고 그 마스터의 점포 안에서만 관리 점포를 고른다. 연결한 가맹 마스터는 나중에 바꾸지 않는다.F-OILWTZ
  • 가맹 마스터를 미사용으로 바꾸면 딸린 가맹 관리자 계정은 미사용, 그 마스터가 만든 권한 그룹은 사용 중지가 된다.F-OILWTZ · F-GSJRKH
  • 사용자 한 명에 권한 그룹 하나. 본인의 상태와 권한 그룹은 스스로 못 바꾸고, 본인이 연결된 그룹도 고치거나 지우지 못한다.F-OILWTZ · F-GSJRKH
  • BP 관리자 그룹은 BP 마스터만, 가맹 관리자 그룹은 만든 가맹 마스터만 만든다(관리계정ID). 권한 코드·유형은 등록 뒤 못 바꾼다.F-GSJRKH · PL-EIMSQF
  • 그룹의 CRUD 는 BP 마스터·가맹 마스터 고정 권한과 설정자 본인 범위를 넘지 못한다. 그룹명은 같은 BP 안에서 유형과 상관없이 겹칠 수 없다.F-GSJRKH · PL-AMTMVC

공통코드 · 휴일

7
  • 공통코드 그룹은 여기서 추가·수정·삭제하지 않는다. BP 가 다루는 단위는 상세 코드뿐이다.F-QPDEWN
  • 플랫폼고정 그룹은 조회만, 플랫폼제공 그룹은 플랫폼 코드를 고치고 코드를 더할 수 있다. BP 가 더한 코드는 BP전용이고 다른 BP 에 안 보인다.F-QPDEWN · PL-VOCZCE
  • 플랫폼 사용자는 BP 를 골라 그 BP 의 공통코드를 조회만 한다.F-QPDEWN
  • BP 휴일은 전체 점포 또는 특정 점포에 건다. 같은 날 둘 다 있으면 둘 다 보이고, 그 점포 업무에는 특정 점포 휴일이 먼저다.F-YQTLQE
  • 전체 점포 휴일은 BP 마스터와 전체 점포 범위 BP 관리자만 바꾼다. 나머지는 자기 매핑 점포의 특정 점포 휴일만.F-YQTLQE
  • 기간은 최대 1년, 반복은 한 번에 730건까지. 종료일 없는 반복은 2년치를 먼저 만들고 배치가 이어 채운다.F-YQTLQE · S-NMSCQK
  • 오늘과 미래 날짜만 등록·수정·삭제한다. 반복 휴일은 이 휴일만·이후 모두·전체 중 범위를 고르고, 지난 날짜는 어느 범위든 그대로 둔다.F-YQTLQE

쟁점

10건 · 미정 10

명세로 정해지지 않아 화면이 갈리는 것만 모았다. 사소한 것은 각 화면 파일 머리 주석에 있다. 목록에서 수정·삭제를 바로 하지 않고 상세를 거치는 것은 목업 규칙으로 정했다 — 휴일 목록 명세(S-YAFRYZ)의 표시 항목과 다르다.

CONFIG-1 일부 점포만 맡은 BP 관리자에게 관리자 목록을 점포 매핑으로 좁혀 보이는가 미정 R-DJGLEO · S-AJHXFU · PL-RWJYLJ
A · 요구사항 수락 기준

목록 데이터는 메뉴 권한과 점포 매핑을 모두 통과한 범위로 제한한다. 직영 4곳만 맡은 이서아는 그 점포의 관리자만 본다.

B · 권한 레벨 정책 · 이 목업

BP 마스터·BP 관리자는 본인 소속 BP 범위의 계정을 본다. 목업은 이쪽을 따라 8명을 모두 보였다.

CONFIG-2 가맹 관리자 계정을 가맹 마스터 말고 누가 바꿀 수 있는가 미정 S-OENTFQ · F-OILWTZ · PL-CUECAY

수정 명세의 처리 절은 다른 역할도 가맹 관리자의 기본정보·권한 그룹·상태를 고칠 수 있게 읽히는데, 규칙·권한 절은 연결된 가맹 마스터만이라고 한다. 계정 상태 정책은 또 가맹 관리자가 다른 가맹 관리자를 미사용으로 바꿀 수 있다고 적었다. 목업은 연결된 가맹 마스터만 고치게 했다.

CONFIG-3 관리자 비밀번호 초기화는 새 초기 비밀번호 메일인가, 재설정 링크인가 미정 S-TKSRJX · S-XKYOND
A · 1팀 명세 · 이 목업

BP·플랫폼 관리자 모두 시스템이 12자 초기 비밀번호를 만들어 계정 이메일로 보내고 첫 로그인에 바꾸게 한다.

B · 3팀 목업 확정값

관리자 초기화는 임시 비밀번호가 아니라 재설정 링크를 보낸다고 정했다(ACC-11 · PRM-04). 두 팀 문서가 다르다.

CONFIG-4 등록 화면에 계정 상태 입력을 두는가 미정 F-OILWTZ · S-NIMSMQ

기능 표시 절은 등록과 수정 화면 모두에 계정 상태 입력 영역이 있다고 하지만, 새 관리자 계정은 사용으로 생긴다(계정 상태 정책). 목업은 등록에서 상태 칸을 빼고 수정에만 두었다. 역할(계정 역할)도 수정에서 바꿀 수 있는지 적혀 있지 않아 읽기 전용으로 그렸다.

CONFIG-5 가맹 관리자 그룹을 지울 때 다른 가맹 마스터의 그룹으로 옮길 수 있는가 미정 F-GSJRKH · S-LYKAEI

대체 그룹은 “같은 BP · 같은 권한 유형”이면 된다고 적혀 있다. 그런데 가맹 관리자 계정에는 연결된 가맹 마스터가 만든 그룹만 붙일 수 있어, 다른 마스터의 그룹으로 옮기면 그 규칙이 깨진다. 목업은 같은 관리계정ID의 사용 중인 그룹만 대체 후보로 보였다.

CONFIG-6 BP 관리자 그룹은 어떻게 사용 중지되는가 미정 F-GSJRKH

권한 그룹은 사용·사용 중지 두 상태인데, 사용 중지로 가는 길은 가맹 마스터가 미사용이 될 때의 가맹 관리자 그룹뿐이다. BP 관리자 그룹을 사람이 직접 멈추는 항목이 없다. 목업의 BA000007 점포 조회 전용은 사용 중지 표본으로만 두었고, 바꾸는 버튼은 그리지 않았다.

CONFIG-7 BP 가 더한 상세 코드는 관리 주체를 따로 저장하는가 미정 S-FHVSAV · PL-VOCZCE
A · BP 공통코드 명세 · 이 목업

BP 가 추가한 상세 코드에는 관리 주체 BP전용과 소속 BP 를 저장한다. 목업은 행마다 플랫폼제공·BP전용을 읽기 전용으로 보였다.

B · 관리 주체 정책

관리 주체는 그룹에서만 정하고 상세 코드는 그룹을 상속하며 따로 저장하지 않는다.

BP 가 고친 플랫폼제공 코드를 플랫폼 원래 값과 나란히 보일지도 정해지지 않았다.

CONFIG-8 “매일 · 종료일 없음” 반복은 2년치만으로 730건 상한에 걸린다 미정 F-YQTLQE · S-UCPMYB

종료일 없는 반복은 2년치를 먼저 만들고, 반복 한 번에 만들 수 있는 휴일은 730건까지다. 매일 반복의 2년치는 730~731건이라 윤년이 끼면 저장이 막힌다. 상한을 올릴지, 먼저 만드는 기간을 줄일지, 매일 반복을 종료일 필수로 할지 정해야 한다.

CONFIG-9 반복 휴일의 날짜를 “이후 모든 휴일”로 바꾸면 나머지 날짜는 어떻게 되는가 미정 S-BXEAEZ

수정 범위(이 휴일만 · 이후 모든 휴일 · 전체 휴일)는 있지만 날짜를 옮길 때 다른 날짜들이 같이 밀리는지, 반복 규칙(요일·주기) 자체를 고치는 수단이 있는지 없다. 대상 점포를 바꾸면 연장 배치가 이어 만드는 날짜도 바뀌는지도 적혀 있지 않다. 목업은 휴일명·설명·대상만 바꾸는 예로 그렸다.

CONFIG-10 휴일 등록은 점포 하나씩인가, 여러 점포를 한 번에 거는가 미정 S-UCPMYB · F-YQTLQE

데이터에는 대상 점포 식별자가 하나뿐이라 한 휴일에 한 점포로 읽힌다. 가맹 마스터가 자기 점포 넷에 같은 휴무를 걸려면 네 번 등록해야 한다. 기간 등록에 반복을 함께 걸 수 있는지, 종일이 아닐 때 시간을 받는지도 없다. 목업은 점포 하나 · 기간과 반복 중 하나 · 시간 없음으로 그렸다.
