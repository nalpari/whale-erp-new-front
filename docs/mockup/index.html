목록 공통 규칙

확정
  • 20건을 넘을 수 있는 목록은 모두 페이지로 나눈다. 직원·계약·명세서·TO-DO·알림·공지·FAQ·문의·도입문의 — 표든 아코디언이든 같다. FAQ 도 한 카테고리에 100건이 쌓이면 표와 다를 게 없다.
  • 페이지당 건수는 사용자가 고른다. 20 · 50 · 100 중 하나이고, 한 번 고르면 모든 목록이 같이 따른다. 기본은 20.
  • 페이지 번호 방식이다. 상세를 봤다가 돌아오면 같은 페이지로 온다. 무한 스크롤은 쓰지 않는다.
  • 홈에 얹힌 요약 표는 나누지 않는다. 상위 몇 건만 보이고 “전체 보기”로 목록 화면에 넘긴다.
  • 이 규칙은 관리자 웹의 것이다. 직원 앱은 기간이 있는 목록을 주·월로 끊고, 기간이 없는 목록은 20건씩 더 보기로 잇는다. 페이지 번호와 건수 선택은 쓰지 않는다 — 직원 앱 문서 쪽 결정이다.
페이저는 data-pager="총건수" 하나로 붙는다. 목업이라 줄은 늘 1페이지 표본이고 숫자만 움직인다. manyfast 에는 목록이 있는 명세 여덟 곳의 표시 슬롯에 같은 줄로 들어 있다.

개요의 정책 섹션

영역 개요마다 정책 섹션이 있다. manyfast 의 규칙·권한 슬롯에서 화면을 가르는 것만 추려 적었고 원문은 manyfast 다. 줄 끝의 코드는 출처 명세이고, 쟁점 확정 배지는 쟁점으로 정한 값이 문서에 들어간 줄, 반영 대기 배지는 목업이 정했지만 문서에 아직 없거나 다른 줄이다. 회의 뒤 manyfast 를 고칠 때 이 섹션도 같이 고친다.
