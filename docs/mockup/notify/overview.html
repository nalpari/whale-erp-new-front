NOTIFY-1 눌러서 들어가면 읽음으로 볼 것인가 확정 · 들어가면 읽음 S-GDUNIT
A · manyfast 문서

이동해도 읽음이 되지 않는다. 읽음은 사용자가 따로 눌러야 바뀐다.

B · 흔한 방식 · 지금 화면

알림을 눌러 들어가면 그것으로 읽음이다. 따로 누를 것이 없다.

문서는 읽었다는 것과 처리했다는 것을 가르려 했다 — 계약 거부 알림을 열어 봤다고 처리가 끝난 것은 아니니까. 그 뜻은 살리되 맡는 자리를 옮긴다. “처리했나”는 원래 업무가 상태로 안다 (거부된 계약은 재발송하기 전까지 거부 상태다). 알림함은 “봤나”만 맡는다. 두 가지를 알림함 하나에 얹으면 읽었는데도 숫자가 줄지 않는 화면이 된다.

딸린 것.
  • 줄마다 있던 읽음 버튼을 뺐다. 눌러 들어가는 것이 곧 읽음이라 따로 누를 일이 없다. “모두 읽음으로”만 남긴다.
  • S-GDUNIT 의 규칙 “이동해도 읽음 처리 여부는 수신자의 읽음 변경 동작에 따라 관리한다”를 고쳐야 한다.
NOTIFY-2 종 아이콘과 알림함 페이지를 둘 다 둘 것인가 확정 · 둘 다 S-GDUNIT
A · 둘 다 · 지금 화면

종을 누르면 최근 몇 건이 뜨고, 거기서 전체 목록 페이지로 넘어간다.

B · 종만

종을 누르면 목록이 다 열린다. 별도 페이지를 만들지 않는다.

문서의 “알림 진입점 또는 알림함”을 그대로 둔다. 종은 미확인 건수와 최근 것을, 페이지는 걸러 보고 지나간 것을 찾는 자리를 맡는다. 종 하나로 시작해 나중에 페이지를 붙이는 것보다 처음부터 자리를 두는 편이 싸다.
